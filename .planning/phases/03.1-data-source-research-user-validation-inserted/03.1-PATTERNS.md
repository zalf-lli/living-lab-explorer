For `export_source_catalogue.py`, the parallel pattern is:

```python
FIELDS = [
    "source_id", "source_group", "source_name", "layer_or_variable", "already_integrated",
    "spatial_coverage", "temporal_coverage", "access_method", "access_url", "format",
    "license", "update_cadence", "citation_url",
    "(AI) ll_relevance", "(AI) pipeline_path", "(AI) integration_complexity", "(AI) integration_notes",
    "decision", "priority", "rationale", "reviewer_comments",
]

out = DATA / "source_catalogue.csv"
with out.open("w", newline="", encoding="utf-8-sig") as f:
    writer = csv.DictWriter(f, fieldnames=FIELDS)
    writer.writeheader()
    for row_tuple in SOURCES:
        sid, sg, sn, lv, ai, sc, tc, am, au, fmt, lic, uc, cu, lr, pp, ic, inotes = row_tuple
        writer.writerow({
            "source_id": sid, "source_group": sg, "source_name": sn,
            "layer_or_variable": lv, "already_integrated": ai,
            "spatial_coverage": sc, "temporal_coverage": tc,
            "access_method": am, "access_url": au, "format": fmt,
            "license": lic, "update_cadence": uc, "citation_url": cu,
            "(AI) ll_relevance": lr, "(AI) pipeline_path": pp,
            "(AI) integration_complexity": ic, "(AI) integration_notes": inotes,
            # Decision columns always blank — human fills these in xlsx
            "decision": "", "priority": "", "rationale": "", "reviewer_comments": "",
        })

print(f"[done] {len(SOURCES)} source/layer entries -> {out}")
```

Key conventions carried over from the analog:
- `encoding="utf-8-sig"` (BOM prefix — makes Excel open CSV correctly on Windows)
- `newline=""` in the `open()` call (required for `csv.DictWriter` on Windows)
- Decision columns always written as empty strings
- Single `print(f"[done] ...")` at the end — same format as analog

### `data/variables_catalogue.xlsx` — `spatial_data` sheet expansion (human-owned, CRUD)

**Analog:** `data/variables_catalogue.xlsx` current `destatis_variables` sheet (existing columns observed via RESEARCH.md §Existing xlsx Inspection Results)

**Existing `destatis_variables` sheet column set** (75 rows, observed via openpyxl inspection):
```
group | variable_key | genesis_table | label_en | label_de | unit_en | unit_de | notes_en | include_yn | priority_1_3 | expert_comments
```
The last three columns (`include_yn`, `priority_1_3`, `expert_comments`) are the human-decision columns — left blank for reviewers to fill.

**Existing `spatial_data` sheet** (4 stub rows, only 3 columns):
```
Topic | URL | Service URL
```
This stub sheet is the direct precursor. The Wave 1 task replaces it entirely with the 21-column schema (Groups A–D).

**Target sheet structure for `source_catalogue` tab** (to replace or rename `spatial_data`):

Group A — Identity (columns 1–5, always filled by script/AI):
```
source_id | source_group | source_name | layer_or_variable | already_integrated
```

Group B — Verified facts (columns 6–13, each row must have citation_url):
```
spatial_coverage | temporal_coverage | access_method | access_url | format | license | update_cadence | citation_url
```

Group C — AI assessment (columns 14–17, header prefix "(AI)" is the D-03 visual separator):
```
(AI) ll_relevance | (AI) pipeline_path | (AI) integration_complexity | (AI) integration_notes
```

Group D — Review decision (columns 18–21, blank; human fills):
```
decision | priority | rationale | reviewer_comments
```

**Critical constraint (from CLAUDE.md):** `data/variables_catalogue.xlsx` is human-owned. The pipeline script must NEVER overwrite it. `export_source_catalogue.py` writes only to `data/source_catalogue.csv`. The xlsx is edited directly by the AI researcher (Wave 2) or the human reviewer, not programmatically regenerated.

The analogy in the existing code: `export_variables.py` never touches `variables_catalogue.xlsx` — it only writes `destatis_variables_catalogue.csv`. The same separation must hold for the source catalogue.

## Shared Patterns

### Path Resolution
**Source:** `data-pipeline/python/export_variables.py` lines 12–14
**Apply to:** `export_source_catalogue.py`
```python
ROOT = Path(__file__).resolve().parent.parent.parent
DATA = ROOT / "data"
DATA.mkdir(parents=True, exist_ok=True)
```
This three-line pattern is universal across all pipeline scripts. Always resolve ROOT as three `.parent` steps from the script file (script is at `data-pipeline/python/`).

### CSV Writer Encoding
**Source:** `data-pipeline/python/export_variables.py` line 97
**Apply to:** `export_source_catalogue.py`, any future CSV-writing script
```python
with out.open("w", newline="", encoding="utf-8-sig") as f:
    writer = csv.DictWriter(f, fieldnames=fields)
    writer.writeheader()
```
`utf-8-sig` (UTF-8 with BOM) is required so Excel on Windows auto-detects encoding. `newline=""` is required for `csv` module on Windows to avoid double line endings.

### JSON Output Pattern (for any JSON outputs written during Wave 2 research)
**Source:** `data-pipeline/python/fetch_destatis.py` lines 464–468
**Apply to:** Any JSON cache files written during Wave 2 source probing
```python
(DATA / "destatis_nuts3.json").write_text(
    json.dumps(nuts3, ensure_ascii=False, indent=2, sort_keys=True), encoding="utf-8"
)
```
Always use `sort_keys=True` (per CLAUDE.md) and `ensure_ascii=False` (German Umlauts in source names).

### Decision Columns — Always Empty in Script Output
**Source:** `data-pipeline/python/export_variables.py` lines 100–103
**Apply to:** `export_source_catalogue.py`
```python
writer.writerow({..., "include_yn": "", "priority_1_3": "", "expert_comments": ""})
```
Decision/review columns are always written as empty strings by the script. Reviewers fill them in the xlsx. The CSV mirror captures whatever is in the xlsx after review (re-exported by pandas `to_csv` in Wave 3). Never pre-fill decision columns except for `already_integrated = "yes"` rows which get `decision = "include"` by convention (D-09).

### Human-Owned File Protection
**Source:** CLAUDE.md critical rule — "Never write `data/ll_content.json` from any pipeline script"
**Apply to:** `export_source_catalogue.py`, all Wave 2 research tasks
The script must never write to `data/variables_catalogue.xlsx`. It only writes to `data/source_catalogue.csv`. The xlsx is human-owned and edited directly (by AI researcher in Wave 2, then human reviewer in Wave 3).

### Print Progress Convention
**Source:** `data-pipeline/python/export_variables.py` line 105
**Apply to:** `export_source_catalogue.py`
```python
print(f"[done] {len(VARIABLES)} variables -> {out}")
```
Single bracketed tag (`[done]`, `[fetch]`, `[cache]`, `[WARN]`) followed by description. The `export_*` scripts use only `[done]` since they have no network calls. Network-calling scripts (`fetch_destatis.py`) use `[fetch]`, `[cache]`, `[retry]`, `[WARN]`.
