<objective>
Do the phase's one real structural refactor — lift `useLayerState` out of the remount-keyed layout
components into `LLDetail` — and teach the site header to carry `?compare=` across Living Lab
switches.

Purpose: D-09 requires the active layer tab to survive entering/leaving comparison, swapping sides,
and switching the primary LL from the header. Today the tab resets because `useLayerState` is
declared inside `LayoutSplit`/`LayoutStacked`, which are remounted by `key={`A-${ll.slug}`}`
(LLDetail.jsx:42). D-04's "hold one LL fixed and sweep the other four past it" workflow is the exact
reason the tab must persist. Both changes are prerequisites for comparison and are independently
verifiable on the single-LL page today.
Output: layer state owned by `LLDetail`, slug removed from the remount keys, `startTransition`
preserved, and header pills that preserve/swap the comparison partner.
</objective>

`<Routes>` (App.jsx:27), so `useParams()` there returns an empty object and `activeSlug` is always
`undefined` — meaning the `active` pill highlight at line 63 is currently dead. D-04's swap rule
needs the real current slug, so replace `useParams` with `useLocation` and parse the pathname:
match `/^\/ll\/([^/]+)/` against `location.pathname` and take capture group 1, falling back to
`undefined`. Remove `useParams` from the import on line 1 if nothing else uses it. This also
restores the intended active-pill highlight — that is a wanted side effect, not scope creep.

**(b) Branch the pill `onClick`.** Add `useSearchParams` to the `react-router-dom` import and read
`const [searchParams] = useSearchParams()` / `const compareSlug = searchParams.get('compare')`.
Replace the `onClick={() => navigate(`/ll/${ll.slug}`)}` handler with this rule set:

| Condition | Navigate to |
|---|---|
| no `compareSlug`, or no `activeSlug` | `/ll/<clicked.slug>` (no search string — today's behaviour) |
| `compareSlug` present and clicked slug === `compareSlug` (clicked LL is the current partner) | `/ll/<clicked.slug>?compare=<activeSlug>` — the two swap sides |
| `compareSlug` present and clicked slug !== `compareSlug` | `/ll/<clicked.slug>?compare=<compareSlug>` — clicked LL becomes primary, partner unchanged |
| clicked slug === `activeSlug` (already primary) | same as the rows above; no special case needed |

Build the partner value as `const nextPartner = ll.slug === compareSlug ? activeSlug : compareSlug`
and pass it through `encodeURIComponent` before interpolating it into the URL — `compareSlug` comes
straight off the URL and is untrusted (threat T-10-03). `ll.slug` comes from validated metadata and
needs no encoding.

Do not change the button JSX, the inline SVG icon rendering (lines 84-91), the pill styling, or the
language switcher. Do not add validation of `compareSlug` against the LL list here — `LLDetail`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL hash (`#/ll/:slug?compare=…&layout=…`) → app state | Fully attacker/user-controllable. Anyone can hand-craft or share a link. |
| `location.pathname` → derived `activeSlug` | Same boundary; parsed with a fixed regex, never used as an object key in this plan. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03 | Tampering (URL/param injection) | `Header.jsx` pill navigation | mitigate | The untrusted `compare` value is passed through `encodeURIComponent` before being interpolated into the navigate target, so a value like `x&layout=B` or `x#/evil` cannot inject extra params or path segments. `ll.slug` is metadata-sourced and used unencoded. |
| T-10-04 | Spoofing (open redirect) | `Header.jsx` pill navigation | accept | All navigation targets are relative in-app paths built as `/ll/${ll.slug}` from the metadata list; no absolute URL, `window.location.href` assignment, or user-supplied host is ever constructed. `HashRouter` further confines navigation to the current document. |
| T-10-05 | Information disclosure | `activeSlug` regex parse | accept | The parsed slug is only compared for equality and re-encoded into a URL; it is never used as an object index or rendered raw in this plan. Object-key lookup of untrusted slugs is handled in plan 03 (T-10-06). |
| T-10-SC | Tampering (supply chain) | npm dependencies | mitigate | Zero packages installed. `git diff --stat app/package.json app/package-lock.json` must print nothing after execution. |
</threat_model>
