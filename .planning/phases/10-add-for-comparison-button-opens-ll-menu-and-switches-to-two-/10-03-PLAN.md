<objective>
Turn the dead "Add for comparison" button into a working partner picker that writes a validated
`?compare=<slug>` into the URL.

still renders the normal single-LL layout, which is the intended intermediate state.

a `ComparePicker` dropdown, and a `CompareCTA` whose button opens it.
</objective>

Add compare state to `LLDetail`, mirroring the existing `?layout` idiom (same `useSearchParams`,
same `new URLSearchParams(searchParams)` clone-then-set pattern). All of the following goes ABOVE the
`if (loading)` early return at line 29, because it contains hooks.

Derived values:
- `const compareSlug = searchParams.get('compare')`
- `const partnerCandidate = compareSlug ? bySlug?.[compareSlug] : null`
- `const partner = partnerCandidate && partnerCandidate.slug === compareSlug && compareSlug !== slug ? partnerCandidate : null`
- `const isComparing = Boolean(partner)`

The `partnerCandidate.slug === compareSlug` identity check is a security requirement, not a
stylistic one: `bySlug` is built with `Object.fromEntries`, so `bySlug['__proto__']`,
`bySlug['constructor']` and `bySlug['toString']` all return truthy inherited values. Without the
identity check, `?compare=__proto__` would put the page into comparison mode with an object that has
no `slug`, `name` or `kpiByTab` and crash the columns in plan 04. (Threat T-10-06.)

Picker options, memoised per CONVENTIONS.md's "derive with useMemo, never useEffect + setState":
- `const compareOptions = useMemo(() => Object.values(bySlug ?? {}).filter((x) => x.slug !== slug).sort((a, b) => a.order - b.order), [bySlug, slug])`

Param writers:
- `const setCompare = (nextSlug) => { ... }` — clone `searchParams`, `next.set('compare', nextSlug)`,
  then `setSearchParams(next)` WITHOUT `replace`, so picking a partner pushes a history entry and the
  browser Back button leaves comparison. (`?layout` uses `replace: true` because it is a preference,
  not a navigation; entering comparison is a navigation. This resolves an unspecified detail of D-01's
  "back-button and shareable links work for free".)
- The invalid-value stripper is the file's one legitimate `useEffect` — a side effect on the URL, not
  derived render state. Guard it in this exact order: return early while `loading` is true or
  `bySlug` is falsy (otherwise a valid param would be stripped during the metadata fetch), return
  early when there is no `compareSlug`, return early when `partner` is truthy; otherwise clone
  `searchParams`, `next.delete('compare')`, and `setSearchParams(next, { replace: true })`. Deps:
  `[loading, bySlug, compareSlug, partner]` with a trailing
  `// eslint-disable-line react-hooks/exhaustive-deps` (same style as `app/src/hooks/useGeoJSON.js`).

Add `useEffect` and `useMemo` to the existing `react` import. Do not touch `App.jsx` — D-01 adds no
route. Do not support a comma-separated list or more than one slug (D-05). Do not render any error
message for an invalid value (D-03).

`isComparing`, `partner`, `compareOptions` and `setCompare` are consumed by tasks 2-3 of this plan and
by plans 04-05; leave them wired to real consumers by the end of this plan so no unused-variable lint
error is introduced.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL hash `?compare=<value>` → `bySlug` object lookup | Fully user-controllable string used as a JavaScript object key. |
| URL hash `?compare=<value>` → DOM | The value is never rendered; only the resolved metadata object's `name` is. |
| `LL_ICONS[slug].paths` → `dangerouslySetInnerHTML` | Build-time static SVG module, indexed by a validated slug. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-06 | Elevation of Privilege (prototype/inherited-property lookup) | `bySlug?.[compareSlug]` in `LLDetail` | mitigate | `bySlug` comes from `Object.fromEntries`, so `__proto__`, `constructor`, `toString`, `valueOf` etc. all resolve truthy. Accept the candidate only when `partnerCandidate.slug === compareSlug`, so only genuine own entries can enter comparison mode. Verified by the `?compare=__proto__` acceptance criterion. |
| T-10-07 | Tampering (XSS via injected SVG) | Picker row icon rendering | mitigate | `dangerouslySetInnerHTML` receives `LL_ICONS[ll.slug].paths` only, where `ll` is an object from validated metadata — never the raw `compareSlug` string. Options come from `Object.values(bySlug)`, not from URL input. |
| T-10-08 | Information disclosure (reflected input) | Invalid `?compare=` handling | mitigate | An invalid value is deleted from the URL and never rendered — no error banner echoes the attacker-supplied string back into the DOM (D-03). |
| T-10-09 | Denial of Service (listener leak) | `useDismissOnOutside` | mitigate | The effect is gated on `open` and its cleanup removes both `keydown` and `mousedown` listeners; asserted by the `removeEventListener` count of 2. |
| T-10-SC | Tampering (supply chain) | npm dependencies | mitigate | Zero packages installed. `git diff --stat app/package.json app/package-lock.json` prints nothing after execution. |
</threat_model>
