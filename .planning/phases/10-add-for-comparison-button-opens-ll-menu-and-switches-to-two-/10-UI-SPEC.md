### Per-Column Brand Accent (resolves D-17/D-18 discretion — exact color source and placement)

**Color source: `ll.outlineColor`** (not `ll.color`) — this is the deliberate, locked answer to the "which brand color" discretion question. `ll.outlineColor` is the exact hex `LLMap` already draws as that LL's boundary line (`LLMap/index.jsx:733-736,789`: `const outlineColor = ll.outlineColor || C.orange`). Using the same field for the column accent means the accent bar, the color chip, and the boundary line the visitor sees inside that very column's map are all one continuous visual signal — not a second, competing "brand color" system. `ll.color`/`ll.colorDark` (used elsewhere for badges/landing cards) are **not** used here.

| Element | Placement | Size |
|---|---|---|
| Column top accent bar | Full column width, very first element in the column (above the header block) | 4px tall, `background: ll.outlineColor`, no border-radius (flush with the column's top edge) |
| Color chip (bar + picker rows) | 8px diameter filled circle, `background: ll.outlineColor`, `border: 1px solid rgba(2,35,34,0.15)` | Positioned immediately before the LL name text in: comparison-bar name buttons, picker dropdown rows |

## Layout & Interaction Contract

### Comparison bar (replaces `LayoutSwitcher`, D-02/D-14/D-15)

Occupies the exact DOM slot `LayoutSwitcher` occupies today (`LLDetail.jsx:40`). Structure, left → right:

1. Hint label: `t('llDetail.comparePrefix')` ("Comparing")
2. Name button A (route slug, always left per D-06): color chip + `llA.name`, `onClick` opens the picker (see below)
3. Separator glyph: `↔` (decorative, `aria-hidden="true"`)
4. Name button B (partner, `?compare=` value): color chip + `llB.name`, `onClick` opens the same picker
5. Swap button: `⇄ Swap` — navigates to `/ll/<llB.slug>?compare=<llA.slug>` (D-06's rewrite-the-route swap)
6. Exit button: `✕ Exit comparison` — navigates to `/ll/<llA.slug>` (strips `?compare=`, keeps `?layout` untouched per D-02)

Both name buttons are functionally identical: because the route slug is always the left column (D-06) and `?compare=` holds exactly one slug (D-05), there is only ever one thing to pick — the partner. Clicking **either** name opens the same picker (pre-populated to exclude the current route slug, per D-12); selecting an LL sets `?compare=<picked>`. This is the specific, locked resolution of D-14's "clicking either LL name reopens the same picker dropdown" — it is one picker, one target slot, regardless of which name triggered it.

### Picker dropdown (D-11/D-12/D-13 — anchored, not modal)

- **Trigger:** the existing `CompareCTA` button (when not comparing) OR either comparison-bar name button (when comparing) — one shared component, re-anchored to whichever element triggered it.
- **Position:** `position: absolute`, anchored to the trigger's bounding box: `top: calc(100% + 6px)`, `left: 0`. Trigger's parent needs `position: relative`.
- **Dimensions:** fixed width `220px`; height auto (4 rows × ~40px + 8px padding ≈ 168px).
- **Chrome:** `background: C.white`, `border: 1px solid ${C.mutedLight}`, `borderRadius: 12px`, `boxShadow: '0 8px 24px rgba(2,35,34,0.18)'`, `zIndex: 1000` (above any map-badge `zIndex: 500` used inside `LLMap`, since this dropdown can visually overlap the map column).
- **Rows:** exactly 4 (five LLs minus the current route slug, D-12 — no disabled state). Each row: `LL_ICONS[slug]` SVG (18px, matching `Header.jsx:84-91`) + `ll.name` (13px/600) + trailing 8px color chip (`ll.outlineColor`). Row padding `8px 12px`, hover/focus background `C.surface`, hover/focus text color `C.orange` (the one picker-specific use of the accent color).
- **Dismiss:** Escape key or outside click — **verbatim port** of `StatPanel`'s `useEffect` dismiss pattern (`StatPanel.jsx:14-29`), same `keydown`/`mousedown` listener pair with cleanup, gated on the dropdown's open boolean.
- **No backdrop, no focus trap, no scroll lock** (D-11 — matches the app having no such primitive anywhere).

### Column structure (D-16, per column)

Top → bottom, single scroll container shared by both columns (D-20):

1. **Accent bar** — 4px, `ll.outlineColor` (new, see Per-Column Brand Accent)
2. **Header block** — badge (`LLBadge size="lg"`, 52px) + name (22px/900) + region (11px/400) + tagline (13px/400), **no `ContactManagerButton`** (D-19). Reuses `LayoutSplit`'s plain white header chrome (`padding: '20px 24px 16px'`, `background: C.white`, `borderBottom: 1.5px solid C.mutedLight`) — **not** `LayoutStacked`'s teal gradient hero (rejected by D-19: both columns would render the same gradient, distinguishing nothing).
3. **`StatPanel`** — `tab={sharedLayer}`, `ll={ll}`, new `maxColumns={2}` prop (D-29 — see Component Modifications)
4. **`LLMap`** — `height={300}` (D-27), independent `Suspense`/`MapFallback` per column (D-24), own legend (D-25), own bounds-fit (D-22)
5. **`BarChart`** — `compact` prop (D-28, already exists, no `BarChart` changes)
6. **Two `TextBlock`s, stacked vertically** (not side-by-side, per D-16) — `t('llDetail.aboutLandscape')` then `t('llDetail.socioEconomicContext')`, each `lines={4}` (shorter than the single-LL page's 5, since the column is narrower and two stacked blocks already use more vertical space than the 2-across grid did)

No `LayerTabs` inside the column (shared, rendered once above both columns, D-07) and no `CompareCTA` inside the column (D-15 — hidden entirely while comparing).

### Two-column grid (D-20/D-21)

`display: grid`, `gridTemplateColumns: '1fr 1fr'`, `gap: 24px` (lg token), one shared `overflowY: auto` on the outer wrapper — **not** on each column. A `1.5px solid ${C.mutedLight}` border on the left column's right edge (matching `LayoutSplit`'s existing `borderRight` divider convention) gives a visible seam between columns without introducing a new border treatment. No media query, no minimum width (D-21).

### Empty-state footprint (D-10)

- **`StatPanel`, zero fields:** instead of `return null` (current `StatPanel.jsx:31`), render one placeholder `div` spanning the full grid width (`gridColumn: '1 / -1'`), same `padding: '12px 16px'` and `border: 1px solid ${C.mutedLight}` as a populated tile, containing the empty-state heading + body copy above. This occupies the same vertical rhythm as a populated KPI row without fabricating fake tiles.
- **`BarChart`, no `CHART_DATA[layer]` entry:** instead of `return null` (current `BarChart.jsx:8`), render the same empty-state copy inside a block with `minHeight: 150px` (approximates a populated compact chart's height) — **only** applied when `BarChart` is rendered inside a comparison column (pass a new `minHeightWhenEmpty` prop, default `undefined`, so the single-LL view's existing null-return behavior is unchanged there).

### Loading & error states for the two maps (D-23/D-24/D-26)

- Both `LLMap` instances mount eagerly and in parallel — no code change needed (`LLMap` is already `React.lazy`; module-scoped caches already shared).
- Each column wraps its own `<Suspense fallback={<MapFallback />}>` — independent, unstaggered (D-24). No shared boundary.
- Layer-load failures render inline inside that `LLMap` instance only, via the existing per-layer error badges — no page-level banner, no new component (D-26).

## Component Modifications

### `app/src/pages/LLDetail.jsx`

- Parse `?compare=` via `useSearchParams` (mirrors the existing `?layout` pattern at lines 19-27); validate against `bySlug` and against the route `slug` (D-03); strip with `replace: true` if invalid or self-referential.
- Lift `useLayerState()` (currently declared separately inside `LayoutSplit` and `LayoutStacked`, lines 115/221) up into `LLDetail` itself, and pass `[layer, setLayer]` down as props — this requires dropping `ll.slug` from the remount `key` on the layout components (currently `key={`A-${ll.slug}`}`/`key={`B-${ll.slug}`}`, line 42) so the tab survives LL swaps (D-09). Flagged in `10-CONTEXT.md` as the phase's one structural refactor.
- Branch: when `?compare=` is valid, render a new `LayoutCompare` component (two columns) instead of `LayoutSplit`/`LayoutStacked`, and render the new `ComparisonBar` instead of `LayoutSwitcher`.
- Hide `CompareCTA` whenever `?compare=` is active (D-15) — both inside `LayoutStacked`/`LayoutSplit` (not reached, since those aren't rendered in compare mode) and confirm no stray render path leaves it visible.

### `app/src/components/Header.jsx`

- Read `?compare=` from the current location; when present, LL pill `onClick` navigates to `/ll/<clicked>?compare=<currentPartner>` (D-04), swapping sides if the clicked LL is already the partner. Requires reading `useSearchParams` (currently not imported) alongside the existing `useParams`.

### `app/src/components/StatPanel.jsx`

- Add `maxColumns = 4` prop; grid `gridTemplateColumns` becomes `repeat(${Math.min(fields.length, maxColumns) || 1}, 1fr)` (line 75). Comparison columns pass `maxColumns={2}` (D-29); single-LL page passes nothing (unchanged behavior).
- Replace the `if (fields.length === 0) return null` (line 31) with the empty-state placeholder block described above, **gated on a new `showEmptyState` boolean prop** (default `false`) so the single-LL page's existing null-return is unchanged there and only comparison columns opt in.

### `app/src/components/BarChart.jsx`

- Add optional `minHeightWhenEmpty` prop (default `undefined`). When `!data` and `minHeightWhenEmpty` is set, render the empty-state block at that min-height instead of returning `null`. When unset (single-LL page), `return null` behavior is unchanged.
