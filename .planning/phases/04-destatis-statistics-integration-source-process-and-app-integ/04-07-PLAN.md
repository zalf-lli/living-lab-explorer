<objective>
Find the correct Regionalstatistik.de table codes for the 15 curated KPI slots that have no
Kreis-level source on GENESIS-Online, fetch their real values, and commit them.

Context that makes this plan likely to succeed where 04-06's retry could not: 04-06 only retried
the *same* GENESIS-Online cube codes (e.g. `41120BJ001`) against Regionalstatistik.de, per its
scope. But Regionalstatistik.de — whose entire purpose is regional (Kreis/Gemeinde) statistics —
publishes its data as dash-suffixed statistic *tables* (e.g. `41120-01-02-4`, where the trailing
`-4` is the regional-depth marker for Kreise), served by `data/tablefile`, not `data/cubefile`.
A live orchestrator probe of `catalogue/tables` with `selection=41120*` on Regionalstatistik.de
returned 15+ Kreis-level farm-statistics tables, confirming both the discovery endpoint and the
code format. The user has additionally confirmed they can see these indicators (or close
equivalents) in reports on the Regionalstatistik.de website.

Purpose: this closes the Phase 4 data gap properly, so Waves 3-5 (kpiByTab / StatPanel UI) can be
built on real data instead of 16/17 nulls.
Output: updated `fetch_destatis.py` with a Regionalstatistik.de table fetch path; committed real
values in `data/destatis_nuts3.json` / `data/destatis_ll.json`; updated
`data/destatis_curated_kpis.json` manifest; passing tests.
</objective>

Regionalstatistik.de specifics (live-confirmed by orchestrator probe, 2026-07-24):
- `catalogue/tables` with `{"selection": "<prefix>*", "pagelength": N, "language": "de"}` returns
  dash-coded tables; trailing `-4` = Kreis level. `-B` suffixed variants also exist (inspect one
  before assuming which variant to prefer).
- Data endpoint for these codes is `data/tablefile` (classic table format), NOT `data/cubefile`.
  Prefer `format=ffcsv` (flat file CSV) if the host supports it — it yields one observation per
  row with explicit column names, far easier to parse robustly than the rendered table layout.
  Verify empirically which formats this host actually serves before building the parser.
- Regionalstatistik.de also offers the `find/find` endpoint for keyword search — useful for
  indicators whose statistic prefix differs from the GENESIS one (e.g. income/GDP may live under
  "Volkswirtschaftliche Gesamtrechnungen der Länder" with a different numbering); the German
  `label_de` values in data/destatis_variables_catalogue.csv are good keyword seeds.
- Regional filtering: tablefile accepts `regionalvariable`/`regionalkey` parameters — passing
  `regionalkey` as a comma-separated list of our 14 AGS codes (values of `NUTS3_TO_AGS`) keeps
  responses small. Verify parameter behavior empirically.
