strategy (D-13/D-14), and run the corrected fetcher end-to-end to produce real committed data. Write a

which app tab, so downstream plans never have to re-derive or hardcode this mapping a second time.

real, trustworthy numbers to show" (Plans 04-03 through 04-05). D-14 explicitly requires that a
failing table gets swapped for a working substitute rather than left empty — this plan implements that
contract in code, not just as an intention.
Output: real, non-placeholder `data/destatis_nuts3.json` / `data/destatis_ll.json`, a
`data/destatis_curated_kpis.json` manifest, `data/destatis_meta.json` fetch timestamp, and pytest
coverage proving the contract.

## Trust Boundaries

| Boundary | Description |

| pipeline -> GENESIS-Online API (`catalogue/tables`, `data/tablefile`) | Additional live API calls for per-table verification; response is untrusted input |
| pipeline -> `data/destatis_variables_catalogue.csv` | Local, human-curated CSV read for fallback candidate lookup |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Information Disclosure | GENESIS error responses in `_verify_table` | accept | GENESIS success/error bodies do not echo request credentials per RESEARCH.md; no additional masking needed |
| T-04-06 | Tampering | Fallback substitution selecting an unintended variable | mitigate | `_resolve_curated_kpis()` only substitutes within the same catalogue `group` and only when the primary table fails live verification; every substitution is explicitly logged with `[WARN]` for auditability |
| T-04-07 | Denial of Service | Repeated live verification calls across 15 unique tables | mitigate | Reuses the existing 3-retry/backoff `_post()`; verification runs once per table per invocation, not per-Kreis |
</threat_model>
