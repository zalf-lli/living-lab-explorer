# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — see "shadcn gate decision" below |
| Preset | not applicable |
| Component library | none — hand-built React components, no Radix/base-ui/MUI |
| Icon library | none (no npm package) — hand-rolled inline SVG icons keyed by i18n id, stroke uses `currentColor`; catalogue lives in `app/src/data/kpi_icons.js` |
| Font | `'Satoshi', system-ui, sans-serif` — declared as `FONT` in `app/src/theme.js`, applied globally in `app/src/styles/global.css` |

**shadcn gate decision:** No `components.json` exists in the repo, and the tech stack is Vite/React (JS only). Per the standard gate this would normally trigger an init prompt. However, `CLAUDE.md` and `REQUIREMENTS.md` explicitly lock this project's approach: *"No TypeScript, no CSS frameworks, no SSR"* and *"Tailwind / CSS-in-JS / CSS modules migration — inline-style-with-theme pattern stays"* is listed under **Out of Scope**. shadcn requires Tailwind as a peer dependency, so initializing it would directly violate a locked project decision. The gate is therefore resolved as **N** without prompting: `Tool: none`. The existing token object `C` in `app/src/theme.js` plus inline `style={{...}}` is this project's design system, and Phase 4's new UI must extend it rather than introduce a parallel system.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, tight inline padding, `marginBottom`/`marginTop` on labels |
| sm | 8px | Compact stack gaps inside a stat panel (e.g. tile `gap`) |
| md | 16px | Default spacing between stat rows / between a panel's title and its body |
| lg | 24px | Panel padding, section-to-section gaps within the detail page |
| xl | 32px | Layout gutters (`LayoutStacked` outer `padding`/`margin`) |
| 2xl | 48px | Not used in Phase 4 — reserved for future full-page section breaks |
| 3xl | 64px | Not used in Phase 4 |

**New Phase 4 components (`StatPanel`/`DataRow` and the source-attribution line) must use only the 4px-multiple values above — no exceptions.** Concretely: `gap: 8` (not 6), `padding: '12px 16px'` (not `'12px 14px'`), `borderRadius: 8` (not 10/14/18). Do not pixel-match the legacy `KPIStrip` tile's non-4-multiple values (`padding: '12px 14px'`, `borderRadius: 10`, `gap: 6`) — those are pre-existing, scoped legacy debt in `KPIStrip`/`BarChart`/`LLDetail` (documented here, accepted as-is, not touched by this phase) and must not be copied into new code. If a future visual pass wants `KPIStrip` and the new `StatPanel` pixel-identical, that requires an explicit follow-up decision to either migrate `KPIStrip` onto the 4px grid or grant `StatPanel` a named, signed-off exception — not a silent default.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 | 1.5 |
| Label | 11px | 700 (uppercase, `letter-spacing: 0.07em`) | 1.2 |
| Heading | 15px | 700 | 1.2 |
| Display | 22px | 900 | 1.1 |

Notes:
- These map directly to existing usages: `Body` = tagline/description text size (`LLDetail` tagline `fontSize: 13`); `Label` = the uppercase eyebrow labels above KPI/stat values (`KPIStrip` label, currently 10px in one place — 11px is the standardized value going forward for any *new* Phase 4 label, the pre-existing 10px KPI label is a grandfathered exception, not a pattern to copy); `Heading` = stat/KPI numeric value size (`KPIStrip` value `fontSize: 15, fontWeight: 700`); `Display` = LL name in the split layout header (`fontSize: 22, fontWeight: 900`). The stacked layout's larger display (26px) is a pre-existing hero-only exception and is not to be reused for Phase 4's new stat panels.
- Exactly two weights in active use for new Phase 4 UI: **400** (regular, body/prose) and **700** (bold, labels/values). Weight 900 is reserved for the existing page-level LL name display only — do not use it for new stat panels.
- **Only these 4 sizes (13/11/15/22px) are in active use for Phase 4 UI.** The source-attribution footer line (see Copywriting Contract) reuses the **Label** size (11px, 700) rather than introducing a fifth size — it is visually distinguished from other Label uses by lower-emphasis color (`C.muted`, not `C.greenMid`) and regular letter-spacing, not by a separate font size.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f9fef9` (`C.bg`) | Page background, scroll area behind cards |
| Secondary (30%) | `#ffffff` (`C.white`) | Stat panel/card backgrounds, KPI tiles, `TextBlock` containers |
| Accent (10%) | `#eb5b25` (`C.orange`) | Reserved for: the "+ Compare" primary CTA button, the active state of the layout-option switcher tab, the light-variant `PreliminaryDataBadge` text/border, and the new "View source" citation link (Phase 4) |
| Destructive | not applicable | Phase 4 is a read-only statistics display; it introduces no destructive actions (no delete/edit/remove affordances) |

Accent reserved for: `CompareCTA` button, active `LayoutSwitcher` tab, `PreliminaryDataBadge` (light variant) text/border, and the Phase 4 "View source" citation link on hover/focus. Never apply accent orange to passive stat values, panel borders, or default (non-active) interactive elements — those use `C.teal` (`#005754`) for numeric/value emphasis and `C.mutedLight` (`#c3e9d8`) for default borders, consistent with `KPIStrip`.

**Primary visual anchor:** within each new stat panel, the bold `C.teal` numeric value (Heading, 15px/700) is the primary visual anchor — labels and the source-attribution line are deliberately lower-emphasis. At the page level, the existing `KPIStrip` row remains the primary anchor above the fold; new stat panels sit below it as secondary, supporting detail, matching the established visual hierarchy rather than competing with it.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Phase 4 introduces no new primary action button. The one new clickable text element is an inline "View source" link, not a CTA button: EN `View source` · DE `Quelle ansehen` — opens the originating GENESIS table page in a new tab, styled as an underlined `C.orange` link at 11px, placed at the end of each stat panel's attribution line. The existing "+ Compare" CTA (`CompareCTA`) is unchanged by this phase. |
| Empty state heading | EN `Pending review` · DE `In Prüfung` — small inline badge/footnote, not a full empty-state screen (this is a per-field state, not a whole-page empty state) |
| Empty state body | EN `Some indicators for this Living Lab are still pending expert review and data verification.` · DE `Einige Indikatoren für dieses Living Lab befinden sich noch in der fachlichen Prüfung.` — shown once per stat panel (not repeated per field) whenever at least one field in that panel has no verified value yet. The per-field placeholder itself renders as a muted em-dash glyph `–` (`C.muted`, not the literal ASCII hyphen `-` used today in `ll_content.json` placeholders), so real zero/low values are never visually confused with "not yet available." |
| Error state | EN `Statistics are temporarily unavailable. Reload the page — if this keeps happening, the data source may be temporarily unreachable.` · DE `Statistiken sind vorübergehend nicht verfügbar. Seite neu laden — falls das Problem bestehen bleibt, ist die Datenquelle möglicherweise vorübergehend nicht erreichbar.` — this is a page-level fetch failure only (the same class of error as the existing `app.metadataErrorTitle`), because Destatis data ships as static committed JSON; there is no per-field runtime fetch to fail once `ll_metadata.json` has loaded. |
| Destructive confirmation | not applicable — no destructive actions in this phase |
| Source attribution (Phase 4 addition) | EN `Source: Destatis GENESIS-Online, table {{tableId}}, retrieved {{date}}` · DE `Quelle: Destatis GENESIS-Online, Tabelle {{tableId}}, abgerufen am {{date}}` — mandatory footer line on every new stat panel, styled at the **Label** size (11px/700, per Typography) but in `C.muted` instead of `C.greenMid` to keep it visually secondary. This line is what visually distinguishes real Destatis-sourced numbers from the app's pre-existing generic "placeholder data" wireframe copy (`llDetail.wireframeNote`) — do not reuse wireframe/placeholder wording once a panel shows real Destatis-sourced values. |

## Implementation Notes for This Phase

- **New component needed:** neither `KPIStrip` nor `TextBlock` currently render `production`/`socio` numeric fields anywhere in the app (`ll.production`, `ll.socio`, and `data/destatis_ll.json` have no frontend consumer yet — confirmed by codebase search). Phase 4 must introduce a new label/value list component (e.g. `StatPanel` or `DataRow`) that:
  - Follows the `KPIStrip` tile visual language (white card, `C.mutedLight` border, uppercase `C.greenMid` label, bold `C.teal` value) rather than the striped-placeholder `TextBlock` pattern, since these are real numbers, not narrative prose — but built on the 4px spacing grid (see Spacing Scale) rather than copying `KPIStrip`'s legacy non-4-multiple values.
  - Renders the per-field empty state (`–` em-dash) and the panel-level "pending review" footnote and source-attribution line defined above.
  - Formats numbers using the active i18n language's locale (`Number(value).toLocaleString(i18n.language === 'de' ? 'de-DE' : 'en-US')`) rather than the browser-default locale currently used unqualified by `KPIStrip` (`ll.area.toLocaleString()`) — German thousands/decimal separators differ from English and these are now real public statistics, not internal placeholder numbers.
- **Open decision flagged by 04-RESEARCH.md (Pitfall 3), not a UI-visual question but affects this contract's empty-state logic:** whether `ll_content.json`'s existing `"-"` placeholder strings in `production`/`socio` blocks are stripped by a human edit, or the merge policy changes to computed-wins for these fields, or `"-"` is treated as an explicit "no override" sentinel. This UI-SPEC assumes the end state either way is "field has a real value" vs. "field has no value yet," rendered per the Empty State row above — the merge-policy mechanism itself is a planning/pipeline decision, not a design-contract one, and should be locked during `/gsd:discuss-phase 4` or plan-phase before the executor builds `StatPanel`.
- **Wireframe context:** `LLDetail.jsx` is still an explicit design-exploration wireframe (`LayoutSwitcher` with Option A/Split vs Option B/Stacked, `llDetail.wireframeNote` = "Wireframe prototype - placeholder data"). New Phase 4 stat panels must render inside *both* existing layouts (`LayoutSplit` and `LayoutStacked`) without assuming either one is final, and must not remove or contradict the existing wireframe note — real Destatis data and wireframe-placeholder narrative text will coexist on the same page until a later phase resolves the layout choice.
