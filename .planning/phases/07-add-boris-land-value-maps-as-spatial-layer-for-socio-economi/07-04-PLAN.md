Add these four module-level functions:

1. `computeQuantileBuckets(collection, bucketCount = 6)` — returns `null` when the collection is empty or
   yields no usable values, otherwise an array of `bucketCount + 1` ascending breakpoints. Collect
   `feature.properties.bodenrichtwert` only from features where `has_current_value === true` AND the value
   is a finite number (D-08 zones are excluded from the quantile maths, not merely from display — this is
   the locked contract). Sort ascending numerically. Compute breakpoint `i` as
   `values[Math.min(values.length - 1, Math.floor((i / bucketCount) * values.length))]` for
   `i` in `0..bucketCount`, then force the last breakpoint to the maximum value so the top bucket is closed.
   The bucket count is fixed at 6 for every Living Lab (D-02 plus the UI-SPEC lock) — do not make it adaptive.
2. `getBucketIndex(value, buckets)` — returns the index in `0..5` for a finite `value` given the breakpoint
   array, using half-open ranges `[breaks[i], breaks[i+1])` with the top bucket closed on both ends. Returns
   `-1` for a non-finite value or a null `buckets`.
3. `getEconomicStyle(feature, buckets)` — when `feature.properties.has_current_value !== true`, or the value
   is not a finite number, or `buckets` is null, return `BORIS_NO_DATA_STYLE`. Otherwise return
   `{ ...BORIS_VALUE_STYLE_BASE, fillColor: BORIS_RAMP[getBucketIndex(value, buckets)] }`. Fill colour
   encodes value only — no border-per-usage-type and no hatching (D-06).
4. `buildEconomicLegendEntries(collection, buckets, lang)` — returns `null` when `buckets` is null and the
   collection has no no-data zones. Otherwise build one `{ value, en, de, color }` entry per bucket, where
   `value` is `bucket-{i}`, `color` is `BORIS_RAMP[i]`, and both `en` and `de` are the same formatted range
   string built from the breakpoints rounded to the nearest whole euro: `` `${lo}-${hi} €/m²` `` (D-04 —
   the exact range, not gradient endpoints). Rounding applies to the *label only*; `getEconomicStyle` keeps
   using the unrounded breakpoints. Implement the UI-SPEC collapsed-bucket rule: if rounding produces two or
   more adjacent buckets with an identical label string, emit a single legend row for the run (keeping the
   lowest bucket's colour) rather than repeated identical rows — the style function still assigns all six
   distinct colours. Finally, if any feature in the collection has `has_current_value !== true`, append a
   last entry `{ value: 'no-data', en: 'No current value', de: 'Kein aktueller Wert', color: BORIS_NO_DATA_STYLE.fillColor }`.
5. `bindEconomicTooltip(feature, layer, t, lang)` — build a wrapper div with `maxWidth = '280px'` and
   `lineHeight = '1.35'`, exactly as `bindSoilTooltip` does, and compose rows through `createTooltipRow`
   (never `innerHTML`). Exactly three information rows, in this order (D-12):
   - Title row (`isTitle = true`): when `has_current_value === true` and the value is finite, the formatted
     value `` `${Number(value).toLocaleString(lang === 'de' ? 'de-DE' : 'en-US')} €/m²` ``; otherwise
     `t('map.economicTooltip.noCurrentValue')` and no numeric value is rendered at all — never present a
     stale historical figure as if it were current.
   - Usage-type row: label `t('map.economicTooltip.usageType')`, value `getLocalizedValue(props, 'usage_type', lang)`.
     Omit the row when that resolves falsy.
   - Valuation-date row: label `t('map.economicTooltip.valuationDate')`, value the `stichtag` formatted with
     `new Date(props.stichtag).toLocaleDateString(lang === 'de' ? 'de-DE' : 'en-US')`. Omit the row entirely
     when `stichtag` is null. When `stichtag` is present but `has_current_value !== true`, append
     `' ' + t('map.economicTooltip.historical')` to the formatted date.
   No zone-reference-code row and no development-status row (D-12 exclusions; `bodenrichtwertNummer`,
   `usage_type_code`, and the development-status fields are provenance-only and are never rendered).
   Bind with `layer.bindTooltip(wrapper, { sticky: true, direction: 'top', opacity: 0.95 })` — the identical
   options object `bindSoilTooltip` and `bindProtectedAreasTooltip` already use.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| static GeoJSON asset -> browser DOM | Every property on a BORIS feature originates from a third-party state WFS and is rendered into tooltips and the legend |
| generated `layer_sources.js` -> info panel link | The attribution `url` becomes an `href` in the info control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-05 | Tampering (XSS) | `bindEconomicTooltip` rendering `usage_type_*` and the formatted value | mitigate | Every tooltip node is built through the existing `createTooltipRow()` helper, which assigns `textContent` and never `innerHTML`.
