<objective>
Land the declarative half of the BORIS pipeline: the bilingual usage-type and development-status semantic
contract, the `sources.yaml` layer registration carrying both states' endpoints and the Wave-0 tuning values,
and the `layer_sources.js` codegen extension that gives the info control its per-state provider records.

Purpose: 07-CONTEXT.md D-11 requires one shared bilingual vocabulary built before anything reaches the
frontend, mirroring the Phase 2.2 `soil_semantics.py` precedent. 07-RESEARCH.md section 3.2 proved that
Brandenburg and Hessen run genuinely different code vocabularies that merely share some letters, so the
lookup must be keyed by `(state, raw_code)` and never by `raw_code` alone.
Output: `boris_semantics.py`, a `boris` entry in `sources.yaml`, an extended `generate_layer_sources()`, and
new contract tests.
</objective>

Functions:
1. `normalise_usage_code(state, raw)` — strip whitespace; for `bb`, accept either a bare numeric code or a
   full `https://registry.gdi-de.org/codelist/de.adv-online.gid/BR_Art_Nutzung/{code}` href and return the

2. `resolve_usage(state, raw)` — returns `(canonical_code, en, de)`. For `bb`, look the normalised code up
   directly in `BR_ART_NUTZUNG`. For `he`, map through `HE_ART_NUTZUNG` first and then into

   vocabularies share letters with different meanings (07-RESEARCH.md section 3.2 anti-pattern), and a
   shared-key lookup would silently mis-map. On any miss return `(normalised_or_None, *UNMAPPED_USAGE)` so
   the raw code survives as provenance. Raise `ValueError` for a `state` other than `"bb"` or `"he"`.
3. `resolve_development_status(state, raw)` — returns `(en, de)` from `ENTWICKLUNGSZUSTAND[(state, code)]`,
   falling back to `UNMAPPED_STATUS`. Bauerwartungsland (`E` / `3000`) is an ordinary row here, deliberately
   not special-cased: D-07 includes it like every other zone.
4. `is_current_value(stichtag, reference)` — implements the W-02 predicate exactly as recorded in
   `07-SPIKE.md`, taking an ISO date string (or None) and the reference value the predicate needs (a cutoff
   date for an absolute rule, or the Living Lab's newest observed Stichtag for the relative rule). Returns
   `False` for a None or unparseable Stichtag. Name the chosen rule id in the docstring.
5. `apply_boris_contract(frame, state, reference)` — mirrors `soil_semantics.apply_runtime_contract`: iterate
   with `itertuples`, build parallel Python lists for `usage_type_code`, `usage_type_en`, `usage_type_de`,
   `development_status_en`, `development_status_de`, and `has_current_value`, then bulk-assign each list onto
   `frame[...]` at the end. Preserve the incoming `bodenrichtwert`, `stichtag`, and `bodenrichtwertNummer`
   columns untouched. Return the frame.

Filtering by usage type is explicitly out of scope: D-05 requires every zone type (agricultural, residential,
commercial, forest) to be present, so this module must never drop a row.
