<objective>
Register the Impact Observatory / Esri / Microsoft 10 m Annual Land Use Land Cover (9-class) dataset in the pipeline registry and build the machinery that turns it into one PMTiles file per Living Lab.

Purpose: D-05/D-06/D-07 require static, offline-reproducible, key-free delivery. D-13/D-14 require per-LL clipping. Per-LL processing is also the only variant that builds inside 16.6 GB of RAM (research measured ~11.6 GB peak for the combined approach vs. ~2.2 GB per LL).
Output: A registered `io-lulc-landcover` layer, a slug-aware `build_pmtiles.py`, and a new `build_land_cover.py` orchestrator. No raster is built in this plan — plan 06-02 executes the build.
</objective>

    CLI: `--layer` defaulting to `io-lulc-landcover`; `--slug` accepting one or more slugs and defaulting to all five keys of `input.tiles`; `--list` printing the slug-to-tile assignment and exiting. Single-LL invocation is required so a 16 GB machine can iterate without rebuilding everything.

    Source acquisition: for each distinct tile needed by the requested slugs, format `input.path_pattern` and `input.download_url_pattern` with the tile id, assemble a shim layer dict of the shape `{"input": {"path": ..., "download_url": ..., "sha256": ...}}` where `sha256` comes from `input.sha256_by_tile[tile]`, and call `ensure_input_available()` on it. Reuse of that helper gets progress reporting, `.partial` atomic replace, and digest verification for free. After a successful download of a tile whose pinned digest is null, print the computed SHA-256 with a line instructing the operator to paste it into `input.sha256_by_tile` in sources.yaml.

    Source validation, run once per tile before any tiling work (this is the build-time input-validation control and the guard against the highest-severity silent bug in this phase): open the tile with rasterio and assert `src.count == 1`, `src.dtypes[0] == "uint8"`, and `src.nodata == 0`, raising with the observed value on mismatch.

    Per-slug build loop:
    1. Build the clip geometry via `build_clip_geometry(layer, src.crs, slug=slug)`.
    2. Compute the class histogram for the slug by masking the source with that geometry and running `numpy.unique(..., return_counts=True)`; print it as a `{class_value: pixel_count}` mapping.
    3. Assert the observed value set is a subset of `{0, 1, 2, 4, 5, 7, 8, 9, 10, 11}` — values 3 and 6 were retired by the v3 model and their presence means the wrong product was fetched.
    4. Assert every observed non-zero value appears in the layer's legend value set, raising a message that names the missing values and states they would render fully transparent. This assertion is what converts the "Rangeland disappears" failure mode from a silent visual bug into a build failure.
    5. Call `build_paletted_geotiff(layer, tile_path, paletted_tif, slug=slug)`, then `build_mbtiles(...)` with `min_zoom`/`max_zoom`/`tile_size` resolved from `build` falling back to `defaults`, then `convert_pmtiles(...)` writing to `output.pmtiles_pattern` formatted with the slug.
    6. Print the output path and its size in MB.

    Temp directory handling: create ONE `tempfile.mkdtemp(prefix="io-lulc-landcover-", dir=data/_cache)` for the whole run and reuse it across all slugs, deleting the intermediate `.tif`/`.mbtiles` between slugs, then `cleanup_temp_dir()` it in a `finally`. Before creating it, sweep any stale `data/_cache/io-lulc-landcover-*` directories left by earlier interrupted runs — a five-slug loop otherwise multiplies the known Windows lock-leak by five.

    Accumulate the per-slug histograms into `data/land_cover_class_histogram.json`, written with `json.dumps(..., indent=2, sort_keys=True)`, mapping slug to `{class_value_as_string: pixel_count}`. Merge into the existing file when only a subset of slugs was rebuilt, so a single-slug rerun does not destroy the other four records. Plan 06-02's legend codegen reads this file to suppress legend rows for classes with no pixels anywhere.

    Do not mosaic 32U and 33U. Research verified geometrically that no Living Lab straddles the tile boundary, so each slug is served by exactly one tile in exactly one UTM zone.

    Note for whoever debugs this on this machine: the venv lives under a non-ASCII path, so any GDAL failure surfaces as `UnicodeDecodeError` from `rasterio/_err.pyx` with the real message destroyed. Never interpret that as file corruption; check path existence, file size, and URL reachability independently.
