</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public AWS S3 bucket → local pipeline | ~290 MB of third-party binary raster is fetched and processed |
| pipeline outputs → committed repo → static host | Generated PMTiles and JS become the app's runtime contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-06 | Tampering | Upstream S3 object replaced between builds | mitigate | Task 2 pins both tile SHA-256 digests in `input.sha256_by_tile`; `ensure_input_available()` raises on mismatch on every later build |
| T-06-07 | Spoofing / Information Disclosure | Land cover fetched over a downgraded transport | mitigate | `download_url_pattern` is `https://` only; `requests` verifies TLS by default; no credentials are transmitted because the bucket is anonymous |
| T-06-08 | Tampering | Hand-edited legend drifts from the colours baked into PNG pixels | mitigate | `generate_land_cover_legend()` codegen plus the "Do not edit by hand" header; `layers.js` imports the generated module rather than declaring hexes |
| T-06-09 | Denial of Service | Oversized or malformed raster exhausts memory during the build | mitigate | Per-LL loop plus the 06-01 validation guards; each LL peaks near 2.2 GB against 16.6 GB physical |
| T-06-10 | Repudiation | Derived CC BY 4.0 data redistributed without attribution | mitigate | `sync.py::generate_layer_sources()` (unchanged) keys `LAYER_SOURCE_INDEX` by `app_layer: landscape`, surfacing provider, licence, attribution and citation in `MapInfoControl` |
</threat_model>
