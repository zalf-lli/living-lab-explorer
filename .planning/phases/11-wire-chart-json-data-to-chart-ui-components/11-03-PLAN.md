<objective>
Create `LineChart.jsx`, the climate tab's chart. Climate is the only `chart_type: "line"` layer: its
JSON carries 4 variables x 2 future horizons of percent change, which the current `BarChart` code path
(6 fake month bars) cannot express at all.

Purpose: without this component the climate tab is the one tab that cannot show its real Phase 9 data,
and the phase goal is unmet for it.
Output: a new `app/src/components/LineChart.jsx` with the same prop shape as `BarChart`
(`{ layer, ll, compact, minHeightWhenEmpty }`) so plan 11-04's three call sites can branch between them
with identical props.

Runs in parallel with plan 11-02 (`BarChart.jsx`); the two touch disjoint files.

Add no charting library. The UI-SPEC locks this component as hand-rolled SVG + inline-styled divs, and
`app/package.json` must not change.
</objective>

Create `app/src/components/LineChart.jsx` exporting
`export function LineChart({ layer, ll, compact = false, minHeightWhenEmpty })` — the same prop shape as
`BarChart` so both can be dropped into the same call site with identical props.

Data wiring, identical in behaviour to `BarChart`:
- `const { data, loading, error } = useChartData(layer, ll?.slug)`
- `lang` / `locale` derived exactly as in `StatPanel.jsx:56-57`
- `loading` -> `<ChartLoading minHeight={minHeightWhenEmpty} />` (always visible, UI-7)
- `error` -> `<ChartError minHeight={minHeightWhenEmpty} />` (always visible, UI-7)
- empty — `data == null` OR `data.lines` is not a non-empty array OR `data.x_axis` is not a non-empty
  array -> `minHeightWhenEmpty == null ? null : <ChartEmpty minHeight={minHeightWhenEmpty} />`
- last child of the root element: `<ChartSourceFooter layer={layer} />` (UI-8)

Layout skeleton, top to bottom:
1. **Legend row** — `display: 'flex', flexWrap: 'wrap', gap: 8, marginBottom: 8`. One item per line:
   an 8px circle (`width: 8, height: 8, borderRadius: 4, background: <line colour>, flexShrink: 0`) and
   the label `line.label?.[lang] ?? line.label?.en` at `fontSize: 11, color: C.black, opacity: 0.65`,
   with `gap: 4` between chip and label (the `xs` spacing token).
2. **Plot area** — a `position: 'relative'` div of `height: compact ? 150 : 200` and `width: '100%'`.
   Task 2 fills it.
3. **X-axis label row** — `display: 'flex'` with two children each `flex: 1, textAlign: 'center'`,
   rendering `x_axis[0].label[lang]` and `x_axis[1].label[lang]` at
   `fontSize: 11, color: C.black, opacity: 0.65, marginTop: 4`. Two equal halves centre their text at
   25% and 75% of the plot width, which is exactly where Task 2 places the two data columns.

Y-scale helper, computed in this task and used by Task 2:
- `const values = data.lines.flatMap((l) => l.points.map((p) => p.value)).filter((v) => Number.isFinite(v))`
- `const rawMin = Math.min(0, ...values)` and `const rawMax = Math.max(0, ...values)` — the domain must
  always include zero, because climate change values legitimately span both signs
- `const span = rawMax - rawMin || 1`, `const min = rawMin - span * 0.1`, `const max = rawMax + span * 0.1`
  (10% padding at both ends)
- `const yPct = (v) => ((max - v) / (max - min)) * 100` — returns a top-offset percentage inside the
  plot area, so `yPct(max)` is 0 and `yPct(min)` is 100
- If `values` is empty, fall through to the empty state rather than dividing by zero.

Colour identity (UI-5) — declare a module-level constant in this file (do not modify `layers.js`):
`const CLIMATE_LINE_COLORS = { gdd: C.orange, bio1: C.orangeDeep, bio12: C.teal, bio18: C.tealMid }`
with a comment noting these are the exact hues already used by `CLIMATE_HEAT_RAMP` / `CLIMATE_WATER_RAMP`
in `layers.js` — zero new hex codes.

Resolve a line's variable id by ARRAY POSITION: `CLIMATE_VARIABLES[i]?.id`, guarded by
`CLIMATE_VARIABLES.length === data.lines.length`. When that guard fails, fall back to cycling the four
colours by index. Record this in the summary: the UI-SPEC's suggested defensive fallback of matching
`t(CLIMATE_VARIABLES[i].labelKey)` against `lines[i].label[lang]` is NOT viable and must not be
implemented — the i18n labels are deliberately abbreviated (`climate.variable.gdd` is "GDD",
`bio1` is "Mean temp.") while the JSON labels are the full pipeline names ("Growing degree days",
"Mean annual temperature"), so the comparison can never match. The length-guarded index mapping is the
locked behaviour.

  <action>
Fill the plot area. Use ONE `<svg>` for the connecting lines only; everything that carries text or must
stay circular is an absolutely-positioned inline-styled div. This split is deliberate: the plot must
stretch to an unknown container width, and a non-uniformly scaled SVG would distort glyphs and circles.

**SVG (lines only).** `<svg viewBox="0 0 100 100" preserveAspectRatio="none" style={{ position: 'absolute',
inset: 0, width: '100%', height: '100%' }} aria-hidden="true">`. One `<polyline>` per line with
`points={\`25,${yPct(p0)} 75,${yPct(p1)}\`}`, `fill="none"`, `stroke={colour}`, `strokeWidth={2}`, and
`vectorEffect="non-scaling-stroke"` — the last attribute is mandatory, otherwise the non-uniform
`preserveAspectRatio="none"` scaling makes stroke width vary with container width. Skip a line whose
points are not both finite.

**Zero reference line.** An absolutely-positioned div at `top: ${yPct(0)}%`, `left: 0, right: 0,
height: 0, borderTop: \`1px dashed ${C.mutedLight}\``. Render it always — the domain always contains
zero by construction. It must sit behind the polylines in stacking order (render it before the `<svg>`).

**Endpoint dots.** For each line and each of its 2 points, an absolutely-positioned div at
`left: ${x}%` (x = 25 or 75) and `top: ${yPct(value)}%`, sized `width: 8, height: 8, borderRadius: 4`,
`background: <line colour>`, `transform: 'translate(-50%, -50%)'`.

**Value labels.** For each point, an absolutely-positioned div at the same `left`/`top`, offset clear of
its dot with `transform: 'translate(-50%, -140%)'`, rendering
`${Number(value).toLocaleString(locale, { signDisplay: 'exceptZero', maximumFractionDigits: 1 })}${unit}`
where `unit = data.unit?.[lang] ?? data.unit?.en ?? ''` (it is `%` in every committed file). Style:
`fontSize: 11, fontWeight: 700, color: <same colour as its line>, whiteSpace: 'nowrap'`. `signDisplay:
'exceptZero'` is the exact option `StatPanel.jsx:152` already uses for its climate delta tiles — reuse
it rather than hand-building a `+` prefix.

React keys: `${lineIndex}-${pointIndex}` for dots and labels, `line-${lineIndex}` for polylines.

Known and accepted limitation to note in the summary and flag for plan 11-05's human verification: with
4 lines and only 2 columns, value labels for lines whose values are close (e.g. rheingau's `+1.0` and
`-6.9` at the 2041-2070 column) can visually crowd. No collision-avoidance logic is in scope — the
reviewer decides at the checkpoint whether it is acceptable.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| climate chart JSON (`app/public/data/charts/chelsa-climate-*.json`) → LineChart render | Same-origin static file from the Phase 9 pipeline. Its `label`, `unit`, `x_axis[].label` and numeric `points[].value` fields are the only fetched values rendered. |
| numeric JSON values → SVG geometry attributes | Fetched numbers flow into `points`, `top` and `left` style values — a string-injection surface if unvalidated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-08 | Tampering (XSS) | Line labels, x-axis labels, unit string | mitigate | All render as JSX text children (React auto-escapes). No `dangerouslySetInnerHTML`; asserted in the Task 2 verify command. |
| T-11-09 | Tampering (SVG attribute injection) | `points` / `top` / `left` computed from `points[].value` | mitigate | Every value passes through `yPct()`, which is pure arithmetic, and non-finite values are filtered out of the domain and skipped when drawing — a string in `value` can never reach an attribute verbatim. |
| T-11-10 | Denial of Service | Line/point count | accept | The pipeline emits exactly 4 lines x 2 points and the render is O(lines x points) with no recursion; a tampered file could only add a bounded number of DOM nodes on a static, unauthenticated page. |
| T-11-SC | Tampering (supply chain) | npm dependencies | mitigate | Zero packages installed; no charting library added (UI-SPEC: "none, by design" — the chart is hand-rolled SVG). `git diff --stat app/package.json app/package-lock.json` must print nothing. |
</threat_model>
