<objective>
Rewrite `BarChart.jsx` so it renders the real, committed, per-Living-Lab chart JSON instead of the
hand-written `CHART_DATA` placeholder — for the agriculture, soil, economic and landscape tabs.

Purpose: This is the core of the phase goal. Today every Living Lab sees the same five fake bars
resolved through a dead-end i18n key set; after this plan the bars are that Living Lab's real computed
composition, truncated to a readable seven rows and attributed to its real data provider.
Output: a rewritten `BarChart.jsx` taking `{ layer, ll, compact, minHeightWhenEmpty }`.

Runs in parallel with plan 11-03 (`LineChart.jsx`); the two touch disjoint files.

Expected intermediate state: `LLDetail.jsx` does not pass `ll` until plan 11-04, so between this plan
and 11-04 the chart slot renders the empty/`null` state on the single-LL page. That is intentional and
is not a defect to "fix" inside this plan — do not add a `CHART_DATA` fallback, and do not edit
`LLDetail.jsx` here.
</objective>

Build the rendered rows with
`buildDisplaySeries(data.series, { lang, otherLabel: t('chart.otherCategory') })` imported from

pre-sorted descending by `pct` and the client must preserve that order (UI-3).

Scale: `const topPct = Math.max(...rows.map((r) => r.pct))` computed over the RENDERED (possibly
truncated) rows, so the first bar is always full width. Guard a `topPct` of `0` so the width expression
cannot produce `NaN`.

Container: `display: 'flex', flexDirection: 'column', gap: compact ? 4 : 8`. The `4` is the spacing fix
required by the UI-SPEC — today's value is `5`, the file's one pre-existing non-multiple-of-4 violation.
Change nothing else about spacing in this file.

Each row is `display: 'flex', alignItems: 'center', gap: 10` (unchanged) with three children, left to right:

1. **Label cell** — `width: compact ? 96 : 120` (widened from today's `64`/`82`), `flexShrink: 0`,
   `textAlign: 'right'`, `display: 'flex', flexDirection: 'column'`. It holds two lines, not two rows:
   - the category name at `fontSize: 11, color: C.black, opacity: 0.65, lineHeight: 1.2` with
     `overflow: 'hidden', textOverflow: 'ellipsis', whiteSpace: 'nowrap'` and a native
     `title={row.label}` attribute so the full string is readable on hover (the app has no tooltip
     primitive outside Leaflet — do not add one);
   - directly beneath it the secondary caption `${Number(row.value).toLocaleString(locale)} ${unit}` at
     `fontSize: 10, color: C.muted, lineHeight: 1.3`, where `unit = data.unit?.[lang] ?? data.unit?.en ?? ''`.
     Render the caption for the Other row too, using its summed value — the summed quantity is
     meaningful for every unit currently in the data (`ha`, `zones`).
2. **Bar track** — unchanged from today: `flex: 1, background: C.mutedPale, borderRadius: 3,
   height: compact ? 14 : 18, overflow: 'hidden'`, containing the fill
   `width: ${(row.pct / topPct) * 100}%, height: '100%', background: row.color, borderRadius: 3,
   transition: 'width 0.45s cubic-bezier(0.4,0,0.2,1)'`. `row.color` comes from `buildDisplaySeries`

3. **Value cell** — `width: 46` (widened from today's `32`, which cannot hold a localized

   `${Number(row.pct).toLocaleString(locale, { maximumFractionDigits: 1 })}%`. Always a percent —
   delete the old `unit.includes('%')` conditional; `pct` is 0-100 across all four bar layers.

React keys: use the row label plus its index (`${row.label}-${i}`), not the label alone — different
Living Labs can repeat a label and the old `b.key` field no longer exists.

Do not add a chart title, a legend, an axis, or any CSS animation beyond the pre-existing bar-width
transition.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chart JSON (`app/public/data/charts/*.json`) → BarChart render | Same-origin static file produced by the Phase 9 pipeline. Its `label`, `unit`, `pct` and `value` fields are the only fetched values rendered by this component. |
| `LAYER_SOURCE_INDEX` (build-time codegen) → footer link | Provider name and URL come from the committed module, never from the fetched JSON. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05 | Tampering (XSS) | Category labels and unit strings from chart JSON | mitigate | Labels render as JSX text children and as a native `title` attribute — both auto-escaped by React. No `dangerouslySetInnerHTML`, no `href`/`src` is ever built from fetched data. Asserted in the Task 2 verify command. |
| T-11-06 | Denial of Service | Row count from an oversized `series` array | mitigate | `buildDisplaySeries` caps the rendered rows at `MAX_BARS + 1 = 7` regardless of input length, so a pathological file cannot blow up the render tree. |
| T-11-07 | Tampering | Non-numeric `pct`/`value` in a tampered file | mitigate | Width is computed from `row.pct / topPct` with a zero-guard, and both numbers pass through `Number(...).toLocaleString(...)`, so a non-numeric field degrades to `NaN` text in one cell rather than breaking layout or throwing. |
| T-11-SC | Tampering (supply chain) | npm dependencies | mitigate | Zero packages installed; no charting library added (UI-SPEC: hand-rolled by design). `git diff --stat app/package.json app/package-lock.json` must print nothing. |
</threat_model>
