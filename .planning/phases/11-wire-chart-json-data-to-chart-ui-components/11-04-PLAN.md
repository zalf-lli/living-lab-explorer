<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route params (`:slug`, `?compare=`) → chart fetch URL | `ll` reaches the charts only as a resolved metadata object from `bySlug`; the chart URL is built from `ll.slug`, which originates in the pipeline-produced `ll_metadata.json`, not directly from the URL bar. |
| build-time i18n resources → DOM | Developer-authored strings rendered as auto-escaped React text children. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-11 | Tampering (path traversal) | Chart URL built from `ll.slug` | mitigate | Call sites pass the `ll` object resolved from `bySlug` in `LLDetail`, so `slug` is always one of the five committed metadata slugs. Phase 10 already added the own-property `partnerCandidate.slug === compareSlug` identity check for the `?compare=` path; this plan reuses that resolved object and introduces no new path from a raw query string into a fetch URL. |
| T-11-12 | Tampering (XSS) | Card title interpolation | mitigate | `t('llDetail.projectionTitle', { layer: t(...) })` interpolates another translation key's value, never user or fetched input, and renders as a JSX text child. |
| T-11-13 | Repudiation / stale UI | Removal of the placeholder module | mitigate | The gate greps `app/src` for `CHART_DATA`, `chart_data`, `charts.` and `barChart.` and fails on any hit, so the fake-data path cannot silently survive in a dead branch. |
| T-11-SC | Tampering (supply chain) | npm dependencies | mitigate | Zero packages installed or removed. `git diff --stat app/package.json app/package-lock.json` must print nothing. |
</threat_model>
