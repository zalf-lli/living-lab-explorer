URL resolution: `const source = LAYER_SOURCE_INDEX.get(layer)`, then
`url = 'data/charts/' + source.id + '-' + slug + '.json'`. Import `LAYER_SOURCE_INDEX` from
`../data/layer_sources.js`. Do NOT hardcode a second `layer -> dataset id` table anywhere in this file

Disabled case: when `layer` is falsy, `slug` is falsy, or `LAYER_SOURCE_INDEX.get(layer)` is undefined,
the hook must return `{ data: null, loading: false, error: null }` without fetching. Hooks must still be
called unconditionally — follow `useGeoJSON`'s shape, where `useState`/`useEffect` run first and the
disabled result is an early return placed after them.

Module-scope `cache` and `inflight` `Map`s keyed by the resolved `url`, exactly as `useGeoJSON` does.
Cache entries are never invalidated — all 25 chart files are static and immutable per session.

Fetch semantics (UI-6), implemented in a module-level `fetchChart(url)` helper:
- `res.status === 404` → resolve the value `null` and cache `null` under that url. This is the
  documented "not yet built" case from `data-pipeline/README.md` / `sync.py`'s
  `[chart] skipped - not yet built`, and is an EMPTY result, not an error.
- `!res.ok` for any other status → throw `new Error('Failed to load ' + url + ': ' + res.status)`.
- `res.json()` rejecting (parse failure) → propagate as an error.
- On any rejection, delete the `inflight` entry before rethrowing (same as `fetchOne`).

Hook state: `useState({ key, data: null, loading: isEnabled, error: null })` where
`key = layer + '|' + slug`. The `useEffect` depends on `[key]` only, with the same
`// eslint-disable-next-line react-hooks/exhaustive-deps` comment `useGeoJSON` carries. Guard async
resolution with a `cancelled` local. If `state.key !== key`, return `{ data: null, loading: true, error: null }`
so a mid-flight layer/LL swap never shows the previous chart's data.

Return `data` as the parsed JSON object itself (not wrapped in an array — that array wrapping is a
`useGeoJSON`-only quirk from its multi-URL support and must not be copied).

`buildDisplaySeries` contract:
- Returns `[]` when `series` is not an array or is empty.
- NEVER re-sorts. The pipeline guarantees `series` arrives pre-sorted descending by `pct` (tie-broken by
  English label) and the client must preserve the incoming order exactly (UI-3). Do not call `.sort()`
  anywhere in this file.
- Each output row is `{ label, value, pct, color, isOther }` where `label` is the resolved string
  `entry.label?.[lang] ?? entry.label?.en ?? ''`, `value` and `pct` are the numbers passed through, and
  `color` is `CHART_RANK_COLORS[index]` for real rows.
- When `series.length <= MAX_BARS`: return one row per entry, all with `isOther: false`.
- When `series.length > MAX_BARS`: return the first `MAX_BARS` entries as real rows, then append exactly
  one synthetic row `{ label: otherLabel, value: <sum of remaining values>, pct: <sum of remaining pcts>,
  color: CHART_OTHER_COLOR, isOther: true }`. Round the summed `pct` with `Math.round(sum * 10) / 10` to
  keep float noise out of the rendered `%`; leave the summed `value` unrounded. The Other row always gets
  `CHART_OTHER_COLOR` and never a `CHART_RANK_COLORS` entry.
- Treat a missing/non-finite `pct` or `value` on an entry as `0` when summing, so one malformed row cannot
  produce `NaN` across the whole chart.

runs in production; the `<= MAX_BARS` path is still required and is verified below with a synthetic input.
