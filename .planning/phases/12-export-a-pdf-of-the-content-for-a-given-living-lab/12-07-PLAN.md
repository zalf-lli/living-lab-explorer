<objective>
Build the non-map content of every tab section: the KPI status boxes, the two narrative text slots,
and the chart.

KPIs are presented as Typst **status boxes** rather than as a table: each indicator is a two-part
stacked box — a brand-accent-filled band carrying the indicator label in white bold, and a white
body carrying the formatted value, its unit, and (for climate) its delta. A three-across grid of
those boxes sits under the section's KPI heading. This mirrors `StatPanel.jsx`'s on-screen tile
layout far more closely than a bordered table does, and keeps four short numbers from reading as a
dense data table in a document whose other content is figures and prose. The theme file's existing
`set table` styling stays untouched — it still serves any incidental table elsewhere in the report.

D-06 is the governing constraint: charts re-plot the existing Phase 9 chart JSON contract rather
than recomputing anything, so the PDF and the live site can never disagree. D-10 requires each tab
section to carry everything the corresponding `LLDetail.jsx` tab shows — KPI values, map, chart, and
both `about` and `challenges` narrative blocks. This plan covers all of that except the map.

RESEARCH.md Pitfall 2 is a real, already-observable data gap rather than a hypothetical: several
Living Labs have empty narrative slots today (`havellandisches-luch`'s `landscape.about`,
`landscape.challenges` and `economic.challenges` are all empty in `data/ll_content.json`), and
`generate_metadata.py` normalizes those to `null`. A naive two-slot layout would print an empty box
beside real text. The null path is therefore a first-class case here, not an afterthought.

Purpose: the textual and quantitative body of the report.
Output: one R module, two new Typst components in the existing report extension, and an Rscript gate
covering all fifty (Living Lab, tab) combinations.
</objective>
