<objective>
Build the shared R foundation every other report module sits on: one file holding the branded
ggplot theme, the palette and string accessors, the per-Living-Lab brand lookup, the boundary
loader, and the map legend helper.

D-22 asks for a "well-organized module within this repo … clean enough to lift into a future project
by copying the file, but not packaged as a standalone installable R package." That shapes the design
directly: plain functions with a consistent `ll_` prefix, no side effects at source time beyond
defining them, and exactly one project-specific input (`data/report_tokens.json`) so lifting the
file into another project means swapping one JSON file.

This is the interface-first plan of wave 4. Plans 12-07, 12-08 and 12-09 all build against the
function signatures locked here, in parallel, without reading each other's code.

Purpose: one source of truth for report styling and data access.
Output: one R module and one runnable Rscript gate that exercises every export against real data.
</objective>

Create `data-pipeline/R/theme_llexplorer.R` implementing the accessor half of the interface block:
`ll_repo_root`, `ll_tokens`, `ll_meta`, `ll_lab`, `ll_str`, `ll_brand`, `ll_boundary`, plus the
three constants `LL_TAB_ORDER`, `LL_TAB_CHART_LAYER` and `LL_FIG`.

`ll_repo_root()` resolves from the `LL_REPO_ROOT` environment variable that `render_reports.py`
sets (plan 12-05), falling back to walking up from this file's own location until a directory
containing both `data/` and `app/` is found. Never use `getwd()` — Quarto changes the working
directory during render.

`ll_tokens()` and `ll_meta()` read their JSON with `jsonlite::fromJSON(..., simplifyVector = TRUE)`
and cache the parsed result in a module-local `new.env()` so ten sections in one document do not
re-parse a multi-hundred-KB file ten times.

`ll_lab(slug)` returns `ll_meta()[[slug]]` and calls `stop()` with a message naming the slug and
listing the known slugs when it is absent. `ll_brand(slug)` returns the three colour fields from
that entry.

`ll_str(key, lang, vars = list())` splits `key` on `.` and walks
`ll_tokens()$strings[[lang]]`, then substitutes every `{{name}}`-style placeholder using the
name/value pairs in `vars`. It must `stop()` on a missing key rather than returning `NULL` or the
key itself — a silently missing string becomes an invisible blank in a printed PDF, which is far
worse than a failed render. Also `stop()` if `lang` is not `"en"` or `"de"`.

`ll_boundary(slug)` reads `data/ll_boundaries.geojson` with `sf::st_read(quiet = TRUE)`, filters on
`ll_slug == slug`, and `stop()`s when the result has zero rows. This mirrors the pipeline's existing
"assert the clip produced something" discipline that CLAUDE.md calls out for BÜK vector data —
a silently empty geometry produces a blank map, not an error.

`LL_TAB_ORDER` fixes the report's section order to the app's own tab-strip order
(`agriculture, climate, soil, economic, landscape` — the order of the `LAYERS` array in
`app/src/data/layers.js`), so a reader moving between the site and the PDF sees the same sequence.
D-09 requires all five tabs; D-11 requires a fixed order but does not specify one, so this is the
planner's chosen resolution and must be recorded as such in a comment.

`LL_TAB_CHART_LAYER` maps each tab to the chart-JSON layer id used in
`app/public/data/charts/<layer-id>-<slug>.json`, exactly as declared by the `chart_pattern` keys in
`data-pipeline/sources/sources.yaml`.

Head the file with a comment recording D-22's intent: this is a lift-and-copy module, its only
project-specific input is `data/report_tokens.json`, and it must not gain package-manager or
project-layout dependencies beyond that.

  <action>
Add the styling half of the interface block to `theme_llexplorer.R`.

`theme_ll_base(base_size = 9)` returns a `ggplot2` theme for charts, built on `theme_minimal()`,
using `ll_tokens()$font`'s first family (falling back to `"sans"` when that family is not registered
on the render machine — check with `systemfonts::match_font` if available, otherwise a simple
`names(grDevices::postscriptFonts())`-style guard, and never let a missing font abort a render).
Colours come from `ll_tokens()$theme`: muted greys for axis text and gridlines, the green family for
titles. Keep gridlines minimal, matching the app's own chart look.

`theme_ll_map(base_size = 8)` returns a map theme: no axis text, no axis ticks, no axis titles, no
panel grid, no panel border, a transparent panel background, legend on the right with a small key
size, and a legend title in the same type scale as `theme_ll_base`'s axis titles.

`ll_legend_df(entries)` normalizes whatever the caller has (a data.frame with `label`/`color`
columns, or a named character vector of colours) into a two-column `data.frame(label, color)` with
`stringsAsFactors = FALSE`, preserving input order. Preserving order matters: several palettes in
this project are ordered ramps (`palettes.economic.ramp` low-to-high) and re-sorting them would
misrepresent the data.

`ll_discrete_map_scale(entries, title = NULL)` returns a list of ggplot2 components that a map
function can add with `+`: a `scale_fill_manual()` whose `values` are `entries$color` named by
`entries$label`, with `limits` and `breaks` set to `entries$label` so every legend row appears in
the given order even when a class is absent from the visible extent, plus a `guides()` call
applying `title` and a single-column legend. Setting `limits` explicitly is what makes the printed
legend faithful for the categorical raster layers — otherwise ggplot silently drops classes that
happen not to occur in one Living Lab's clip, and the legend would stop matching the web app's.

Keep `LL_FIG`'s dimensions consistent with an A4 page inside the Typst template's text block:
`width_full` is the full text width in inches, `width_half` roughly half of it, and `dpi` matches
the `fig-dpi: 150` set in `template.qmd` (plan 12-05). If plan 12-05's rendered page geometry turns
out to differ, adjust `LL_FIG` here and note it in the SUMMARY rather than overriding dimensions
chunk by chunk later.

| T-12-25 | Information disclosure | Fields exposed from `ll_metadata.json` | mitigate | `ll_lab()` returns the whole entry, which includes `manager` and `contact`. Plan 12-10's assembly must not render those fields; this module documents that constraint in `ll_lab()`'s comment so a later author does not add them casually |
| T-12-26 | Denial of service | Repeated parsing of large JSON/GeoJSON | mitigate | `ll_tokens()` and `ll_meta()` cache in a module environment; `ll_boundary()` reads a small pre-simplified boundary file rather than the full NUTS geometry |
