  <action>
Create `data-pipeline/R/_toolchain.py` exposing `find_quarto_bin()`, `find_r_home()` and
`require_toolchain()` exactly as named in the interfaces block, structured like
`_sources.find_rio_bin()`.

`find_quarto_bin()` resolution order: the `QUARTO_BIN` env var when set and the path exists;
then `shutil.which("quarto")`; then the known Positron-bundled Windows path
`%LOCALAPPDATA%/Programs/Positron/resources/app/quarto/bin/quarto.exe`. On failure raise
`RuntimeError` naming the `QUARTO_BIN` override and pointing at quarto.org.

`find_r_home()` resolution order: the `R_HOME` env var when set and the directory exists; then the
parent directory of `shutil.which("Rscript")`'s directory; then the highest-versioned
`C:/Program Files/R/R-*` directory on Windows. On failure raise `RuntimeError` naming `R_HOME` and
stating R must be installed and either on PATH or pointed at by `R_HOME`. A set-but-nonexistent
`R_HOME` must raise, never silently fall through to a different R.

`require_toolchain()` calls both and returns a dict with keys `quarto`, `r_home` and `env`, where
`env` is `os.environ.copy()` with `<r_home>/bin` prepended to `PATH` and `R_HOME` set. This is the
concrete fix for RESEARCH.md Pitfall 1 — Quarto detects R chunks from file content and fails at the
knitr engine step with no R-specific detail when R is missing from the subprocess PATH.

Create `data-pipeline/R/README.md` documenting: what lives in `data-pipeline/R/` (report generation
only, not a data-fetching tier); required external tools (Quarto >= 1.4, which bundles Typst, and
R >= 4.5); the Windows PATH friction point and both fixes (`R_HOME=C:\Program Files\R\R-4.5.0`, or
adding its `bin` directory to PATH); the `renv::restore()` command a fresh machine runs; and an
explicit statement that `sync.py` never invokes Quarto (D-04) — reports are rendered by hand via
`python data-pipeline/R/render_reports.py`, the same contract every `build_*.py` script already has.

In `CLAUDE.md`, extend the External CLI deps bullet under Key Constraints so it names `pmtiles`,
`rio`, `quarto` and `R`, keeps the existing `PMTILES_BIN` note, adds `QUARTO_BIN` and `R_HOME` as
the corresponding overrides, and notes parenthetically that R is commonly installed but absent from
PATH on Windows. Also add a `python R/render_reports.py` line to the Pipeline fenced block under
Development Quick Start so the manual render step sits beside `build_pmtiles.py`.

In `.gitignore`, ignore the renv runtime directories that must never be committed (the library and
staging directories under `data-pipeline/R/renv/`) while leaving `renv.lock`, `.Rprofile` and
`renv/activate.R` tracked. Add a short comment stating that `renv.lock` is the committed artifact,
matching the file's existing commented-ignore style.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CRAN / the internet → developer machine | `install.packages()` executes third-party install scripts with the developer's privileges |
| Environment variables → subprocess invocation | `QUARTO_BIN` / `R_HOME` steer which executable later plans run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-SC | Tampering | CRAN package installs (renv, maptiles) | mitigate | Task 2 is a blocking human checkpoint that must clear before Task 3 installs anything; Task 3's acceptance criteria assert `Source: Repository` / `Repository: CRAN` in renv.lock so no package can slip in from an arbitrary GitHub remote; renv.lock is committed so the exact versions are reviewable and reproducible |
| T-12-09 | Tampering | `_toolchain.py` executable discovery | mitigate | Env-var overrides are honoured only when the target path actually exists, and a set-but-missing override raises rather than silently falling back to a different binary — a stale or hostile override cannot cause a quiet substitution |
| T-12-10 | Elevation of privilege | Quarto/R subprocess environment | accept | `require_toolchain()` returns a PATH-augmented environment for developer-run builds only; this pipeline never executes on a server or in response to untrusted input, and the developer already has full local privileges |
| T-12-11 | Information disclosure | renv.lock contents | accept | The lockfile records only public CRAN package names, versions and repository names; no credentials, tokens or absolute user paths are committed (verify no `Source: Local` entries carrying a machine path appear) |
</threat_model>
