<objective>
Publish the ten committed reports to the app's static assets and lock the whole contract behind
tests.

`sync_reports()` is a near-exact copy of `sync_charts()` with one extra axis: reports vary by
(Living Lab, language) rather than by (layer, Living Lab). `_pattern_to_glob()` already tolerates any
number of placeholders — it was built for climate's three — so the two-placeholder report pattern
needs no change to that shared helper.

D-04 is the constraint that shapes this plan more than any other: `sync.py` copies, it never
renders. That mirrors Phase 9's D-11 chart precedent exactly, and it is why `render_reports.py`
stays a manual developer command.

RESEARCH.md's Open Question 2 is resolved here: the report pattern lives as a module-level constant
in `sync.py` rather than as a new `sources.yaml` stanza, because a report is not a per-layer artifact
and `sources.yaml`'s `layers:` schema has no natural home for one.

Purpose: the last pipeline step, and the moment the app-side control from plan 12-03 comes alive.
Output: one new sync function, one orchestration call, ten published copies, four new tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `data/reports/` → `app/public/data/reports/` | Binary artifacts are copied into the directory the static host serves publicly |
| Published PDFs → the internet | Anything inside these files becomes publicly downloadable |
| Glob pattern → filesystem copy | A pattern with two placeholders drives a copy loop |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-51 | Information disclosure | Publishing report contents to a public host | mitigate | Plan 12-10 forbids rendering manager and contact fields and asserts no `@` character appears in a rendered report's extracted text; this plan copies bytes and adds no new content path |
| T-12-52 | Tampering | Copy path escaping the repository root | mitigate | `sync_reports()` delegates to `_sync_matched_pattern()`, which already carries the repo-root-escape guard every other `sync_*` function inherits — the new function adds no independent copy code |
| T-12-53 | Tampering | A published copy diverging from its source | mitigate | `test_report_fixtures_published_to_app_public` asserts byte identity for all ten and an exact published count of ten, so neither a stale copy nor an orphan from a renamed pattern can survive the suite |
| T-12-54 | Denial of service | Repository and deployment bloat from binary duplication | mitigate | `test_report_sizes_within_budget` asserts the per-file, source-total and two-copy-total caps with actionable failure messages, following the project's Phase 7 and Phase 8 precedent for binding footprint caps |
| T-12-55 | Spoofing | Filename drift silently disabling the feature | mitigate | Task 3 derives the expected filename set from `LL_SLUGS` and asserts set equality with the published directory, so a mismatch fails the suite instead of manifesting as a permanently invisible button under D-18's fail-closed behaviour |
| T-12-56 | Elevation of privilege | sync.py gaining the ability to execute a renderer | mitigate | Acceptance criteria assert `sync.py` contains no `subprocess`, `quarto` or `render_reports` reference, keeping D-04's copy-only contract mechanically enforced rather than merely documented |
| T-12-SC | Tampering | npm/pip/cargo installs | mitigate | No installs; this plan adds only standard-library Python and uses already-pinned test dependencies |
</threat_model>
