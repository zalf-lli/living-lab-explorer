# Phase 12 — UI Design Contract

> Visual and interaction contract for the one new UI surface Phase 12 adds to the app: a
> "Download PDF report" control beside `CompareCTA` in `app/src/pages/LLDetail.jsx`. Everything
> else in this phase (Quarto/Typst/R report generation, `sync.py` plumbing) is pipeline-side and has
> no UI surface — this contract covers only the trigger control. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.

**Locked by `12-CONTEXT.md` (do not re-decide):** placement (right of `CompareCTA`, D-15),
single-language link matching the active UI toggle (D-16), hides during comparison mode
alongside `CompareCTA` (D-17), whole section omitted (not disabled) when the file 404s (D-18).
This document only specifies what those decisions left open: the concrete visual/interaction
details.

## New Component: `DownloadReportCTA`

A new component, sibling to `CompareCTA` in `app/src/pages/LLDetail.jsx` (or extracted to its own
file — planner's choice), rendered at both existing `CompareCTA` call sites:

- **Compact** (`LayoutSplit`, right sidebar, currently line 552)
- **Full** (`LayoutStacked`, currently line 727)

It is **not** rendered inside `ComparisonColumn` (the component mounted during comparison mode) —
this is how D-17's "hides during comparison" requirement is satisfied structurally, with no extra
conditional (`ComparisonColumn` never imports `CompareCTA` or this component today).

```jsx
// Props contract
<DownloadReportCTA compact ll={ll} lang={lang} />   // compact instance
<DownloadReportCTA ll={ll} lang={lang} />           // full instance (compact defaults to false)
```

- `ll` — the current Living Lab object (`ll.slug`, `ll.name` used)
- `lang` — `'en'` \| `'de'`, the app's current normalized language (`normalizeLanguage(i18n.language)`
  from `app/src/i18n.js`), **not** a language picked independently by this control (D-16)

**Availability check (implements D-18):** the component determines whether
`data/reports/report-{ll.slug}-{lang}.pdf` exists (however the executor implements the check —
e.g. a small `useReportAvailability(slug, lang)` hook mirroring `useChartData.js`'s
fetch-with-404-as-null pattern at `app/src/hooks/useChartData.js:7-27`). See **Interaction
States** below for the exact three-state contract (`checking` / `available` / `unavailable`) and
which of those render the section.

## Layout & Placement

### Full instance (`LayoutStacked`, current line 726-728)

Current code:
```jsx
<div style={{ padding: '16px 32px 32px' }}>
  <CompareCTA options={compareOptions} onPick={onPickCompare} />
</div>
```

Becomes:
```jsx
<div style={{ padding: '16px 32px 32px', display: 'flex', gap: 16, alignItems: 'stretch' }}>
  <div style={{ flex: '1 1 auto', minWidth: 0 }}>
    <CompareCTA options={compareOptions} onPick={onPickCompare} />
  </div>
  <div style={{ flexShrink: 0 }}>
    <DownloadReportCTA ll={ll} lang={lang} />
  </div>
</div>
```

`gap: 16` matches the row-gap already used for the adjacent two-column text-block grid at line
693 in the same layout. `CompareCTA` gets `flex: 1 1 auto` (grows/shrinks to fill remaining
space — this **is** the "CompareCTA shrinks leftward" behavior D-15 specifies); the download
control keeps its intrinsic content width via `flexShrink: 0`.

### Compact instance (`LayoutSplit`, current line 552, inside the `gap: 18` sidebar stack at line 496)

Current code:
```jsx
<CompareCTA compact options={compareOptions} onPick={onPickCompare} />
```

Becomes:
```jsx
<div style={{ display: 'flex', gap: 16, alignItems: 'center' }}>
  <div style={{ flex: '1 1 auto', minWidth: 0 }}>
    <CompareCTA compact options={compareOptions} onPick={onPickCompare} />
  </div>
  <DownloadReportCTA compact ll={ll} lang={lang} />
</div>
```

`gap: 16` — the same row-gap used between the two controls in the full instance, kept identical
here rather than introducing a second, smaller "compact-only" gap value. This still reads as a
tighter sub-grouping within the outer sidebar stack's `gap: 18` because 16px is visually close to
18px while conforming to the app-wide 4px spacing grid (see Spacing Scale below); it does not need
to be numerically smaller to read as a nested row. `alignItems: 'center'` (not `'stretch'` as in
the full instance) because, per the density rule below, the compact download control is a single
short pill, not a full-height card — centering it vertically against `CompareCTA`'s taller
two-line compact card looks correct; `stretch` would not, since the pill has no natural
"stretch-to-fill-height" content.

### Deliberate content-density difference between compact and full

The **full** instance mirrors `CompareCTA`'s own DOM shape exactly (bordered card, title, body
line, pill button) — matching D-15's "should visually match `CompareCTA`'s existing styling"
literally, at 1:1 structural parity.

The **compact** instance does **not** wrap in a second title+body card. The sidebar column is
narrow (the tagline text next to it is capped at `maxWidth: 380`, line 487) and already holds one
two-line `CompareCTA` compact card; a second full card butted against it would either wrap
awkwardly or force `CompareCTA`'s title to truncate. Instead, compact `DownloadReportCTA` renders
as a single pill button with no outer bordered card — the same reduction `ContactManagerButton`
already makes (that component is also a bare pill, no card, positioned next to page-header text).
This still "visually matches" because the pill itself reuses `CompareCTA`'s own action-button
palette and type scale (orange fill, 16px radius, same font-size/weight scale) — see Color and
Typography below. This is a deliberate progressive-disclosure decision, not an oversight: full
context has room for the explanatory sentence, compact context does not.

## Spacing Scale

The project does not use an abstract spacing-token module — `theme.js` exports only colour and
font constants; every component (including `CompareCTA`, the styling anchor for this contract)
hardcodes literal pixel values inline. `CompareCTA` itself hardcodes some off-grid values (e.g.
`7px`/`20px`) that predate this contract. This new component does **not** copy those off-grid
literals verbatim; instead every declared value below is rounded to the nearest multiple of 4
**and** drawn from the project's standard 4px-grid set (4, 8, 16, 24, 32, 48, 64), matching D-15's
actual requirement ("should visually match `CompareCTA`'s existing styling") without inheriting
`CompareCTA`'s own pre-existing off-grid debt:

| Token | Value | Usage in this component |
|-------|-------|---------------|
| icon-label gap | 8px | Between the `⬇` glyph and the button's text label — rounds up from `ContactManagerButton`'s off-grid `gap: 6` (line 35) to the nearest standard-set value; visually indistinguishable at this size |
| row gap (compact) | 16px | Between `CompareCTA` (compact) and `DownloadReportCTA` (compact) |
| row gap (full) | 16px | Between `CompareCTA` (full) and `DownloadReportCTA` (full) |
| button padding (compact) | `8px 16px` | Pill button padding — rounds `CompareCTA`'s own compact button padding (`7px 16px`, line 1166) up to the nearest standard-set value on the off-grid axis |
| button padding (full) | `8px 24px` | Pill button padding — rounds `CompareCTA`'s own full button padding (`8px 20px`, line 1166) to the nearest standard-set value; kept visually roomier than the compact instance to preserve the existing compact/full size distinction |
| button radius | 16px | Pill radius — rounds `CompareCTA`'s button radius (`20px`, line 1167) and `ContactManagerButton`'s button radius (`24px` equivalent, line 37) to the nearest standard-set value; at this button's line-height (~32px tall), 16px radius still renders as a fully-rounded pill |

Every value above is a multiple of 4 and a member of the standard 4/8/16/24/32/48/64 set — no
exceptions. This is a deliberate, minor visual delta from `CompareCTA`'s own literal (off-grid)
padding/radius values, not an error: D-15 requires this control to "visually match `CompareCTA`'s
existing styling," which is satisfied by matching colour, font scale, and pill shape (see Color
and Typography) — it does not require pixel-exact literal reuse of values that are themselves
off-grid relative to the rest of the codebase.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Button label (compact) | 12px | 700 | 1.2 | The pill button's visible text, compact instance — matches `CompareCTA`'s own compact button (line 1171) |
| Button label (full) | 13px | 700 | 1.2 | The pill button's visible text, full instance — matches `CompareCTA`'s own full button (line 1171) |
| Card title (full only) | 14px | 700 | 1.2 | `DownloadReportCTA`'s title line, full instance — matches `CompareCTA`'s full title (line 1150) |
| Card body (full only) | 12px | 400 | 1.4 | `DownloadReportCTA`'s one-line description, full instance — matches `CompareCTA`'s full body (line 1154) |

Exactly 2 weights (400, 700) and 3 distinct sizes (12, 13, 14px) — within the 3-4 size budget. The
12px size is reused in two places (compact button label and full card body) rather than being a
separate 4th value. No typography is introduced beyond what `CompareCTA` already uses at each
equivalent role.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `C.bg` / `C.white` | Page and card background this control sits on — unchanged, inherited from the surrounding layout |
| Secondary (30%) | `C.limePale` bg + `C.lime` border | Full-instance card surface only (matches `CompareCTA`'s card exactly, line 1140/1143) |
| Accent (10%) | `C.orange` | Reserved for: the pill button's fill (both compact and full) and the `⬇` glyph inside it. Nothing else in this component uses orange. |
| Destructive | not applicable | No destructive action exists in this control — it only downloads a static file; there is no delete/remove/undo affordance |

**Deliberate deviation from `CompareCTA`'s border style:** `CompareCTA`'s full card uses a
**dashed** border (`2px dashed ${C.lime}`, line 1143) — dashed borders are this app's existing
signal for an "add / not-yet-configured" affordance (matches the "Add for comparison" copy).
`DownloadReportCTA`'s full card uses the **same** `C.lime` colour and `2px` width but a **solid**
border, because the report is a complete, ready artifact, not something the user is being invited
to configure — solid vs. dashed is the one intentional visual differentiator between the two
cards, everything else (fill colour, palette, button style) matches closely, with padding/radius
rounded to the app's 4px spacing grid (see Spacing Scale above).

Accent reserved for: the download button's background fill and its icon glyph — never any text,
border, or card background in this component.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (full) | "Download PDF" — button label, full instance |
| Primary CTA (compact) | "PDF" — button label, compact instance (terse by design; card title carries no separate text in compact mode, see Layout & Placement) |
| Card title (full only) | "Download the full report" |
| Card body (full only) | "Every KPI, map and chart for this Living Lab in one PDF document" |

| Error state | **Same as empty state — fail closed, no visible error UI.** A non-2xx response, a network failure, or an unresolved check are all treated as "don't show the control" (see Interaction States); this is a secondary/optional feature, not one that should surface a broken-link or error toast to the visitor |
| Destructive confirmation | not applicable — no destructive action in this control |

## Interaction States

| State | Trigger | Visual result |
|-------|---------|----------------|
| `checking` (availability unresolved) | Component just mounted; the existence probe for `data/reports/report-{slug}-{lang}.pdf` hasn't resolved yet | **Renders exactly as `available` (optimistic).** The control is sized and shown immediately, assuming the file exists. This keeps `CompareCTA`'s shrink stable from first paint in the expected common case (all 10 reports exist per D-21's pytest gate) and avoids a layout flash-then-pop-in on every page load. |
| `available` | Probe resolves 2xx / file confirmed present | Full styled control as specified above (card+button full instance, bare pill compact instance) |
| `unavailable` | Probe resolves 404, any other non-2xx status, or a network error | **Component renders `null`.** `CompareCTA` reflows to its natural full width (the `flex: 1 1 auto` wrapper absorbs the freed space). This transition (available-assumed → hidden) is the **only** layout shift this control can cause, and only in the missing/broken-file case — accepted as a rare, rollout-only condition, not a steady-state UX cost. |
| Default (button, resting) | — | As styled (orange fill, white text, `cursor: pointer` set inline exactly as `CompareCTA`'s own button already does, line 1173) |
| Hover | Mouse over the button | **No bespoke hover treatment.** The project has zero `:hover`/`:focus` CSS anywhere in `app/src` today (confirmed by search) — `CompareCTA`'s own button and `ContactManagerButton` both rely on native browser affordances only. This control matches that existing precedent rather than introducing new interaction machinery unique to itself. |
| Focus (keyboard) | Tab to the button | **Native browser focus ring only.** Do not set `outline: none` anywhere in this component (neither `CompareCTA` nor `ContactManagerButton` do either) — this is the one non-negotiable baseline accessibility requirement even though the rest of the app doesn't otherwise customize focus styling. |
| Active / click | Click or Enter/Space on the button | **No custom click feedback.** This is a plain `<a href="data/reports/report-{slug}-{lang}.pdf" download="report-{slug}-{lang}.pdf">` — the browser's own native download UI (download bar / "Save As" dialog, depending on browser settings) takes over immediately on click. No spinner, no toast, no disabled-while-downloading state — matches `ContactManagerButton`'s plain `mailto:` anchor, which also has zero custom click handling. |

**Why an `<a download>` and not `target="_blank"`:** every other external link in this codebase
(`StatPanel.jsx`, `ChartStates.jsx`, `LLMap/index.jsx`) uses `target="_blank" rel="noopener
noreferrer"` because those links leave the site to a third-party source page. This link stays
same-origin and points at a file the phase's own copy explicitly calls a "download" (`llDetail.downloadReportAction` = "Download PDF" / roadmap phase title itself says "Export a PDF" / "download"), so the native `download` attribute is the correct signal — it asks the browser to save the file rather than navigate to/render it in-tab. Set the `download` attribute's value to the exact filename (`report-{slug}-{lang}.pdf`) so the saved file is never ambiguously named `report.pdf` across five Living Labs' downloads.

## Accessibility

- `aria-label` on the anchor: `t('llDetail.downloadReportAria', { name: ll.name })` — announces
  which Living Lab's report this downloads, since the visible button text alone ("PDF" / "Download
  PDF") does not carry that context.
- `title` attribute mirrors the `aria-label` value, giving a native hover tooltip — same pattern as
  `ContactManagerButton` (line 31).
- The `⬇` glyph is wrapped in `<span aria-hidden="true">⬇</span>` (matching `ContactManagerButton`'s
  `<span aria-hidden="true">✉</span>` at line 49) so screen readers announce only the real label
  text, not a redundant "downwards arrow" description.
- No `outline: none` anywhere (see Interaction States — Focus).
- Because the whole section is omitted (not disabled) when unavailable (D-18), there is no
  `aria-disabled` state to manage and no risk of a focusable-but-non-functional control reachable
  by keyboard/screen-reader users.
