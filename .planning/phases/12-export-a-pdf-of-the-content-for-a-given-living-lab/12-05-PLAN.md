<objective>
Stand up the document skeleton and the render driver: one parameterized Quarto document, one shared
Typst extension carrying five per-Living-Lab brand configs, and a Python script that turns those
into ten PDFs.

This plan deliberately renders a title page and nothing else. Content (KPIs, maps, charts, narrative)
arrives from plans 12-06 through 12-09 and is assembled by plan 12-10. Getting the toolchain,
parameterization and brand plumbing proven end-to-end first means the content plans never have to
debug Quarto mechanics.

RESEARCH.md's Open Question 3 is settled here empirically: whether `--metadata brand:<path>` on the
CLI actually reaches Quarto's brand resolution, or whether the render script must materialize the
brand path into a per-render document instead. Both paths are specified below; Task 2 picks one by
running it.

Purpose: prove the D-01/D-04/D-05/D-08 mechanism before any content depends on it.
Output: a working extension, five brand files, a skeleton document, a render driver, ten title-page PDFs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub (iat-dml/templates) → repo | A third-party Typst/Quarto extension is vendored into this repository and executed at render time |
| CLI arguments → `quarto render` subprocess | Slug and language values become subprocess arguments |
| `ll_metadata.json` → generated brand YAML | Colour values from a machine-written file are written into YAML consumed by Typst |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-19 | Tampering | Vendored third-party Quarto extension | mitigate | Task 1 vendors a copy into the repo (rather than resolving it from the network at each render), records upstream URL, fetch date, license and every local modification, and the whole directory is committed and therefore reviewable in diff; no `quarto add` step pulls code at render time |
| T-12-20 | Elevation of privilege | Typst template and R chunks executing at render time | accept | Quarto executes R code by design and this is a developer-run offline build; the inputs are all repo-local committed files. Accepted because there is no untrusted input path into the render and no server executes it |
| T-12-21 | Tampering | Subprocess argument construction in `render_reports.py` | mitigate | Argument lists only, never `shell=True` (asserted in acceptance criteria); slugs originate from `data/ll_boundaries.geojson`'s own properties, not from user input |
| T-12-22 | Tampering | Generated `brands/<slug>.yml` | mitigate | Generated programmatically from `ll_metadata.json` (a pipeline-written file) and from the committed `_brand.yml`; each file carries a do-not-hand-edit header so a manual edit is visible in review and overwritten on the next render |
| T-12-23 | Denial of service | Render loop | mitigate | `render_one()` asserts the `%PDF-` magic bytes per file and raises with the slug, language and exit code, so a partial or corrupt render fails the run instead of silently producing a broken artifact |
| T-12-SC | Tampering | npm/pip/cargo installs | mitigate | No npm, pip or cargo installs occur in this plan; the only new dependency surface is the vendored extension covered by T-12-19, and the CRAN packages already cleared by plan 12-02's blocking human checkpoint |
</threat_model>
