Prepare the app-side foundations for Phase 12's download control and for the offline R report's
string needs, without touching any rendering component yet.

Three things ship here:
1. `app/src/i18n.js`'s big `resources` literal moves into a new, pure, dependency-free

plan changes what a user sees today.

  <action>
Create `app/src/hooks/useReportAvailability.js` exporting `useReportAvailability(slug, lang)`
returning a plain boolean.

Copy `useChartData.js`'s fetch mechanics as-is: a module-level `const cache = new Map()`, a
module-level `const inflight = new Map()`, one `fetch(url)` per URL with the in-flight promise
shared across concurrent callers, and a `cancelled` flag in the effect cleanup. Differences from
the analog, all deliberate:

- Use `fetch(url, { method: 'HEAD' })`. The consumer never needs the PDF bytes, only an existence
  signal, and a GET would pull multiple MB per page view. Static hosts serve HEAD for static
  assets; if a HEAD response is not `ok` and its status is not `404`, treat it as unavailable
  rather than throwing (see next bullet) so an unsupported-HEAD host degrades to "hide the
  control" instead of surfacing an error.
- Resolve to a boolean, never throw to the consumer: `r.ok === true` caches `true`; `404`, any
  other non-2xx status, and any rejected promise (network failure, abort) all cache `false`.
  UI-SPEC's Copywriting Contract locks "fail closed, no visible error UI" for the error state, so
  unlike `useChartData` this hook has no `error` channel at all.
- Return `true` while the probe is unresolved. UI-SPEC's `checking` row locks optimistic
  rendering so `CompareCTA`'s flex shrink is stable from first paint. Concretely: initialise state
  to `true`, and when the memo `key` changes ahead of the effect resolving, return `true` rather
  than a loading sentinel.
- Return `false` immediately when `slug` or `lang` is falsy (no fetch issued).

Build the URL as `` `data/reports/report-${slug}-${lang}.pdf` `` — a relative path with no leading
slash, matching `useChartData.js`'s own construction, which is what keeps the app working under
`base: './'` sub-path hosting (CLAUDE.md static-hosting constraint).

Guard the path segments before interpolating: only issue a fetch when `slug` matches
`/^[a-z0-9-]+$/` and `lang` is exactly `'en'` or `'de'`; otherwise return `false` without
fetching. This closes T-12-05 (a slug reaching this hook from a router param or a `?compare=`
value must never be able to escape `data/reports/` or smuggle a query string into the URL).

Head the file with a comment explaining the D-18 contract (a false return means the whole
download section is omitted from the DOM, not disabled) and the optimistic `checking` behaviour,
so a future reader does not "fix" the optimistic default into a loading state.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Router param / query string → `useReportAvailability` args | `slug` originates from `/ll/:slug` and `?compare=`; both are attacker-controllable in a crafted link |
| Browser → static host | The HEAD probe crosses the network to whatever origin the SPA is hosted from |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-05 | Tampering | `useReportAvailability` URL construction | mitigate | Task 3 gates the fetch on `slug` matching `/^[a-z0-9-]+$/` and `lang` being exactly `en` or `de`; a slug containing `../`, `?`, `#` or a protocol never reaches `fetch` |
| T-12-06 | Information disclosure | HEAD probe target | mitigate | URL is relative with no leading slash, so it can only resolve same-origin under the app's own `base`; no absolute or cross-origin URL is constructible |
| T-12-07 | Denial of service | Probe volume | mitigate | Module-level cache plus in-flight de-duplication means at most one HEAD per (slug, lang) per session; HEAD (not GET) means no multi-MB body transfer on every page view |
| T-12-08 | Information disclosure | Error surface | accept | Fail-closed by design (UI-SPEC error state) — no status codes, paths or messages are rendered to the user; the control simply disappears |
| T-12-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs occur in this plan; `package.json` dependencies are untouched. The phase's only new packages are CRAN packages, gated by plan 12-02's blocking human checkpoint |
</threat_model>
