<objective>
Build the three maps that come from vector geometry: the soil choropleth, the land-value
choropleth, and the cover-page locator.

D-13 makes per-map legends a correctness requirement rather than styling, and these two thematic
layers are exactly why: soil's on-map legend is built dynamically per Living Lab from the loaded
GeoJSON's own property values, and Phase 7 D-09 locks BORIS to per-Living-Lab quantile buckets. A
single shared or simplified legend would misrepresent both. Each of these functions therefore
computes its legend from the same data the map paints from, reproducing the browser's own logic.

D-14 splits basemap usage cleanly: the cover locator gets tiles plus a Germany inset; the five
per-tab thematic maps get boundary outlines and no tiles, because tiles would compete visually with
dense choropleth data.

Purpose: three of the report's fourteen figures, and the two whose legends are most likely to go
silently wrong.
Output: one R module and an Rscript gate that renders all three map types for all five Living Labs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Tile provider (internet) → build machine | `maptiles::get_tiles()` fetches remote imagery during an offline build |
| Committed GeoJSON → ggplot geometry and legend labels | Feature property values become printed legend text |
| `data/_cache/` → repeat renders | Cached tiles are read back on subsequent runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-34 | Information disclosure | Outbound tile requests | mitigate | Tiles are fetched from exactly one code path (asserted: `get_tiles` appears once) for one bounding box per Living Lab, and only during a developer-run build. No end-user request triggers a fetch, so no visitor's IP or viewport ever reaches the tile provider — unlike a client-side basemap |
| T-12-35 | Tampering | Cached tile imagery reused across renders | accept | The cache lives under the already-gitignored `data/_cache/`, is never committed, and produces a visual artifact a human reviews at plan 12-10's checkpoint; a poisoned cache would be visible, not silent |
| T-12-36 | Denial of service | Large GeoJSON reads (34 MB / 30k zones) | mitigate | Task 2 requires vectorized bucket assignment with no per-feature loop, and each file is read once per map; the acceptance criteria render the largest Living Lab explicitly rather than only the small ones |
| T-12-37 | Tampering | Feature property values becoming legend labels | mitigate | Legend labels come from controlled fields (`soil_group_*`, rounded numeric bucket bounds) produced by this project's own validated pipeline, and are emitted as ggplot text rather than as Typst markup |
| T-12-38 | Repudiation | Silent legend divergence from the web app | mitigate | Task 4's node-versus-R parity assertions fail the gate when the soil legend set or the economic breakpoints drift — the two failure modes that would otherwise produce a plausible-looking but wrong printed map |
| T-12-39 | Denial of service | Network unavailable at render time | mitigate | Task 3 requires a warm-cache offline render to succeed, and a cold-cache failure to name the cache directory and provider explicitly so the one network-dependent step is unmistakable |
| T-12-SC | Tampering | npm/pip/cargo installs | mitigate | No installs; `maptiles` (or the approved `ggspatial`/`rosm` fallback) was cleared by plan 12-02's blocking human checkpoint and is pinned in `renv.lock` |
</threat_model>
