<objective>
Build the single bridge that lets the offline R report reuse the web app's own colours and strings
instead of re-declaring them.

D-07 requires the report to reuse the app's brand tokens and per-layer legend palettes; D-13 makes
per-map legends a correctness requirement because soil and BORIS legends are computed per-Living-Lab
rather than read from a fixed palette. R cannot import a `.js` module, and several of these palettes
have no Python-side source at all (`soil_legend.js` is hand-authored and explicitly documented as
never generated by `sync.py`). Hand-copying hexes into R would guarantee drift the first time
someone tunes a colour.

The answer is a small `node` script that imports the app's already-pure ES modules and emits one
deterministic JSON bundle, `data/report_tokens.json`. This follows the exact precedent
`app/scripts/check_soil_palette.mjs` already set: a standalone node tool that imports
`app/src/data/soil_legend.js` directly, with no dependencies and no bundler.

Purpose: every map legend, chart colour, brand colour and label in the PDF traces back to the same
source the browser paints from.
Output: one generator script, one committed JSON artifact, one contract test.
</objective>

  <action>
Create `app/scripts/export_report_tokens.mjs`, a dependency-free node ESM script that imports the
seven pure app modules named in read_first and writes `data/report_tokens.json` (repo-root relative,
resolved from `import.meta.url` the way `check_soil_palette.mjs` resolves its own paths — never
from `process.cwd()`).

Assemble exactly the shape in the interfaces block. Concretely:
- `theme` is `{ ...C }` from `app/src/theme.js`; `font` is that module's `FONT` export.
- `palettes.agriculture` is `LANDUSE_LEGEND`, `palettes.landscape` is `LAND_COVER_LEGEND`, both
  emitted verbatim (they already carry `value`, `label.en`, `label.de`, `color`).
- `palettes.soil` transcribes the seven soil exports under the key names in the interfaces block.
  Do not call `getSoilColor` here — R reimplements the FNV-1a fallback hash in plan 12-08 and needs
  the raw `groups` map and the ordered `fallback` array, not resolved outputs.
- `palettes.economic.ramp` is `BORIS_RAMP`, `noDataFill` is `BORIS_NO_DATA_STYLE.fillColor`, and
  `bucketCount` is the literal `6` that `computeQuantileBuckets` defaults to in
  `app/src/components/LLMap/index.jsx`.
- `palettes.climate.variables` is `CLIMATE_VARIABLES` and `palettes.climate.legend` is
  `CLIMATE_LEGEND`, both verbatim.
- `chart.maxBars` is `MAX_BARS`, `chart.rankColors` is `CHART_RANK_COLORS` and `chart.otherColor`
  is `CHART_OTHER_COLOR`, all from `app/src/lib/chartSeries.js`. The report's bar charts reproduce
  the app's truncation and rank-colouring behaviour for the economic tab, which has no category
  legend of its own, so these must come from the same module rather than being re-picked.
- `strings.en` is `resources.en.translation` and `strings.de` is `resources.de.translation`, both
  whole. Do not subset by namespace — subsetting creates a maintenance list that silently rots when
  a later phase adds a key the report wants.

Serialize deterministically: a recursive key-sorting replacer so every object's keys are emitted in
sorted order, two-space indentation, and exactly one trailing newline. CLAUDE.md's
`json.dumps(..., sort_keys=True)` rule exists to keep pipeline JSON diffs meaningful, and this
artifact is subject to the same reasoning even though it is written by node rather than Python.
Arrays must keep their source order — `SOIL_FALLBACK_PALETTE`'s index order is load-bearing (it is
what the FNV-1a hash indexes into) and `BORIS_RAMP`'s order is the low-to-high value ramp.

Do NOT write any timestamp, git hash or generator version into the file. A `generated_at` field
would make every regeneration a diff and defeat the determinism check.

Fail loudly with a non-zero exit and a descriptive message if any expected export is missing or
empty (for example `SOIL_GROUP_COLORS` not having 12 entries, `BORIS_RAMP` not having 6, or
`CLIMATE_VARIABLES` being empty) — the script is the only thing standing between a refactor in
`app/src/data/` and a silently wrong PDF legend.

On success print one summary line per palette (name and entry count) followed by `OK`, matching
`check_soil_palette.mjs`'s output convention.

Add `"export:report-tokens": "node scripts/export_report_tokens.mjs"` to `app/package.json`'s
`scripts` block, immediately after `check:soil-palette`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `app/src/**` JS modules → node script execution | The generator executes application source at build time |
| `data/report_tokens.json` → R render | Colour strings from this file are interpolated into ggplot2 scales and Typst output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-15 | Tampering | Colour values flowing from JSON into ggplot/Typst | mitigate | Task 3's `test_report_tokens_shape` asserts every colour matches `^#[0-9a-f]{6}$`, so a value that could act as a Typst or R expression rather than a colour literal cannot reach the render undetected |
| T-12-16 | Information disclosure | Full translation objects committed to `data/` | accept | `app/src/i18n_resources.js` is already public client-side code shipped in every browser bundle; re-emitting it into a repo file discloses nothing new |
| T-12-17 | Tampering | Generator importing application source | mitigate | The script imports only pure, side-effect-free modules under `app/src/` (`theme.js`, `data/*.js`, `i18n_resources.js`) and node built-ins — asserted by the acceptance criterion forbidding any other import; it never imports React, i18next, or anything that touches the network or filesystem at import time |
| T-12-18 | Repudiation | Silent palette drift between app and PDF | mitigate | `test_report_tokens_agree_with_sources_yaml` fails the suite when the app's legends change without a regenerated bundle, so a PDF can never quietly ship a stale legend |
| T-12-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs; the generator is dependency-free by construction and `app/package.json`'s dependency blocks are untouched (only the `scripts` block gains one entry) |
</threat_model>
