<objective>
Wire the computed coverage values from `data/protected_area_kpis.json` into the app's runtime
metadata, mark the two slots as honestly resolved from BfN, and close the regression gap that would
otherwise let the values silently vanish.

Purpose: Phase 4 built the whole `kpiByTab` read path already — `StatPanel.jsx`, `useLLMetadata.js`
and the `kpi.natura2000_ha` / `kpi.nature_reserves_ha` i18n labels (EN and DE) all exist and need
**zero changes**. The only missing link is the merge step. Per **D-03**, that merge happens in
`generate_metadata.py` at build time, keeping the geodata-derived values out of the
destructively-regenerated `data/destatis_ll.json`. Per **D-02**, `source_host` gains a new
`"bfn_wfs"` enum value so a resolved slot identifies where it came from. Per **D-01**, no new KPI
slot is minted: the manifest stays at 17 entries with 4 landscape entries, so both hardcoded count
assertions remain untouched.

Per **D-05**, three test functions are affected and two of them MUST be edited in the same commit as
the manifest change. The non-obvious one is `test_destatis_resolved_slots_have_real_values()`: it
looks up every non-null-`source_host` slot in `data/destatis_nuts3.json`, where `natura2000_ha` and
`nature_reserves_ha` are `null` for all 14 Kreise. Flipping `source_host` to `"bfn_wfs"` without
also narrowing that test's guard turns a passing suite red.

Output: filled landscape KPIs in `data/ll_metadata.json` and `app/public/data/ll_metadata.json`.
</objective>
