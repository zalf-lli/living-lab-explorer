<objective>
Create the pipeline script that turns Phase 5's protected-areas geometry into the two per-Living-Lab
coverage numbers the landscape tab is missing, and produce `data/protected_area_kpis.json`.

Purpose: `natura2000_ha` and `nature_reserves_ha` are two of the six curated KPI slots Phase 4 left
permanently `null` because nature-conservation area statistics are not Destatis products. Phase 5's
BfN WFS layer is the only path to filling them. Per **D-01**, this phase fills exactly those two
pre-existing slots and adds **no percentage KPI**. Per **D-03**, the computed values land in a new
`data/protected_area_kpis.json` file rather than being patched into `data/destatis_ll.json`, because
`fetch_destatis.py`'s `aggregate_ll()` regenerates the entire per-LL record from NUTS3 sums on every
full re-run and would silently wipe an in-place patch.

Per **D-04**, this plan has a hard sequencing dependency on Phase 5: it consumes
`data/geojson/protected-areas-{slug}.geojson`, which does not exist until Phase 5 executes. Task 1
makes that dependency a loud, named failure rather than a silent no-op.

Output: `data-pipeline/python/compute_protected_area_coverage.py`, `data/protected_area_kpis.json`.
</objective>

  <action>
Create `data-pipeline/python/compute_protected_area_coverage.py` as a standalone pipeline script
(NOT registered in `sources.yaml` — it produces no map/tile layer, so it follows the
`fetch_destatis.py` / `generate_metadata.py` hardcoded-path pattern, not the `kind: raster|vector`
registry pattern).

Module-level constants:
- `ROOT = Path(__file__).resolve().parent.parent.parent`, `DATA = ROOT / "data"` — mirror
  `generate_metadata.py`'s path derivation exactly.
- `METRIC_CRS = "EPSG:25832"` (ETRS89 / UTM 32N). This is mandatory. Do NOT use `EPSG:4326`
  (degrees — `.area` is meaningless) and do NOT use `EPSG:3857` (Web Mercator inflates area by
  roughly 60 percent at this project's 50-52 degrees N latitude band, even though
  `build_pmtiles.py` uses 3857 for an unrelated buffer operation).
- `PROTECTED_PATTERN = "data/geojson/protected-areas-{slug}.geojson"`.
- `BOUNDARIES_FILE = DATA / "ll_boundaries.geojson"`.
- `OUTPUT_FILE = DATA / "protected_area_kpis.json"`.
- `DESIGNATION_GROUPS`, a dict mapping each output variable key to the exact set of `designation`
  strings it dissolves: `"natura2000_ha"` -> `{"Natura 2000 SCI", "Natura 2000 SPA"}` (SCI and SPA
  are unioned into one figure because they heavily overlap on the ground and the slot name is
  singular), and `"nature_reserves_ha"` -> `{"Naturschutzgebiet"}`. These two groups are dissolved
  independently — a parcel that is both Natura 2000 and NSG legitimately counts toward both totals,
  mirroring the two independent official statistics series `32121BJ001` and `32141BJ001`.

Implement `category_ha(frame, designations, ll_geom) -> float`:
- Filter `frame` to rows whose `designation` is in `designations`.
- If the filtered frame is empty, return `0.0` — a genuinely measured zero is a valid value here,
  not an error. (Contrast with the clip-produced-zero-features case in `build_vector.py`, which
  raises; that guards a query bug upstream, which is Phase 5's concern, not this script's.)
- Dissolve with `subset.geometry.union_all()` into a single shapely geometry BEFORE any clip or
  area call. This is Pitfall 3: without the dissolve, overlapping same-designation BfN polygons
  double-count their shared hectares.
- Intersect the dissolved geometry with `ll_geom` using `.intersection(ll_geom)`. Use
  `.intersection()` (not `gpd.clip()`) because the operand is a single pre-dissolved shapely
  geometry, not a GeoDataFrame — same GEOS predicate, one operation instead of N.
- Return `round(intersected.area / 10_000, 1)` — square metres to hectares, 1 decimal place
  matching the project's existing `area_ha` convention.

Implement `compute_for_slug(slug, boundaries_metric) -> dict`:
- Resolve the input path as `ROOT / PROTECTED_PATTERN.format(slug=slug)`. If it does not exist,
  raise a `RuntimeError` whose message names the missing file path AND states that Phase 5
  (`data-pipeline/python/fetch_protected_areas.py`) must run first. This is D-04's hard sequencing
  dependency made loud — the failure mode to prevent is a script that silently no-ops on a missing
  file and leaves the KPI slots null.
- `gpd.read_file(path)`, then immediately `frame.geometry = frame.geometry.make_valid()`. This is
  required by CLAUDE.md for every `read_file()` call and is NOT redundant with Phase 5's own
  `make_valid()`: the `to_json()`/`read_file()` round trip does not guarantee validity survives,
  and `union_all()`/`intersection()` raise `TopologyException` on invalid input.
- Assert the frame is non-empty and that `designation` is among its columns; raise a message naming
  the file if either fails.
- `frame = frame.to_crs(METRIC_CRS)`.
- Take `ll_geom` from `boundaries_metric` for this slug.
- Compute both values via `category_ha`.
- Also compute, per group, the naive `float(subset["area_ha"].sum())` of the unclipped source
  property and the feature count, for the plausibility gate in Task 2. Emit these alongside as
  `natura2000_source_sum_ha`, `natura2000_feature_count`, `nature_reserves_source_sum_ha`,
  `nature_reserves_feature_count`. These extra keys are safe because the downstream consumer looks
  values up by exact `variable_key`, never by iteration.
- Return the per-LL dict.

Implement `main()`:
- `argparse` with `--ll SLUG` (optional). Read `BOUNDARIES_FILE`, assert `ll_slug` is a column and
  `crs` is not None, then `.to_crs(METRIC_CRS)` once and reuse for every LL.
- Always iterate ALL slugs present in `ll_boundaries.geojson` when writing. `--ll` is a
  diagnostic-only filter: it prints the computed numbers for that one LL prefixed `[dry-run]` and
  exits WITHOUT writing, so a partial run can never corrupt the committed file. Raise, listing the
  available slugs, if `--ll` names an unknown slug.
- Build the output as `{"_meta": {...}, "<slug>": {...}, ...}`. `_meta` carries `computed_at` (a
  UTC ISO-8601 string), `source` = `"bfn_wfs"`, `metric_crs` = `"EPSG:25832"`, and `input_pattern`
  = the `PROTECTED_PATTERN` value. Keeping the timestamp in a single top-level `_meta` block rather
  than repeating it per LL means an unchanged re-run produces a one-line git diff, not five.
  `_meta` is never read by the metadata merge, which only ever does a lookup keyed by an LL slug.
- Write with `json.dumps(payload, ensure_ascii=False, indent=2, sort_keys=True)` per CLAUDE.md.
- Print `[input]` lines per LL, and a final `[ok] wrote data/protected_area_kpis.json` line.

Build output paths as `DATA / "protected_area_kpis.json"` and
`ROOT / PROTECTED_PATTERN.format(slug=slug)` where slug comes only from the repo-owned
`ll_boundaries.geojson` — never string-concatenate a caller-supplied path (threat T-05.1-01).
  </action>
