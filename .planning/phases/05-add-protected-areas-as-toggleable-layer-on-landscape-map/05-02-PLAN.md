  <name>Task 1: Confirm the protected-areas control shape (overlay toggle vs. exclusive tab)</name>
  <action>Present the decision below to the developer and wait. Do not modify any source file
  until an option is selected. Record the selected option id in the plan SUMMARY.</action>
  <decision>Should protected areas be an independent overlay toggle that can be shown on top of the currently selected thematic layer, or a fifth exclusive tab that replaces it?</decision>
  <context>
    The two locked decisions conflict with the draft UI spec.

    05-CONTEXT.md says users can "independently toggle the protected areas layer on/off **alongside**
    the land-use layer" (domain), that it is "a separate independent toggle, **not forced along
    with** land-use" (D-05), and that it "always renders **on top of** land-use layer" (D-06).

    05-UI-SPEC.md section 2.5 instead proposes adding it to `LayerTabs`. `LayerTabs` is exclusive
    (`active === l.id`, radio behaviour), so selecting a protected-areas tab hides land-use
    entirely. Under that design D-06 is unimplementable — the two layers can never be on screen
    together, so there is no stacking order to honour.

    05-UI-SPEC.md is a Claude-derived artefact ("User Input: None required — all design decisions
    derived from locked CONTEXT"), whereas D-05/D-06 are the user's locked decisions. The planner
    therefore drafted this phase for Option A. This checkpoint exists because the change alters the
    visible UI shape and overrides the drafted spec.
  </context>
  <options>
    <option id="option-a">
      <name>Option A — independent overlay toggle (planned default, recommended)</name>
      <pros>Honours D-05 and D-06 literally; protected areas can sit on top of land-use, soil or any future layer; strictly more capable than a tab; all frontend changes stay inside `LLMap/index.jsx`, `layers.js` and `i18n.js` — `LayerTabs.jsx` and `LLDetail.jsx` are untouched; Leaflet pane ordering makes "always above the raster" structurally guaranteed.</pros>
      <cons>Adds a small in-map toggle control that does not exist in the current design language; deviates from the drafted 05-UI-SPEC.md section 2.5.</cons>
    </option>
    <option id="option-b">
      <name>Option B — fifth exclusive tab</name>
      <pros>Matches 05-UI-SPEC.md section 2.5 verbatim; zero new UI affordance; one-line change to `LAYERS`.</pros>
      <cons>Makes D-06 vacuous — land-use is never rendered while protected areas are visible; arguably violates D-05's "not forced along with land-use" reading of independence; would require re-narrowing five `layerConfig?.type === 'vector'` gates in `LLMap` that currently assume soil is the only vector tab (05-RESEARCH.md Pitfall 11).</cons>
    </option>
  </options>
  <resume-signal>Select: option-a or option-b. If option-b is selected, STOP this plan and request a replan of 05-02 and 05-03 — do not improvise the tab variant on top of the overlay-shaped tasks below.</resume-signal>
