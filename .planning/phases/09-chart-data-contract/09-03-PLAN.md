<shared_conventions>
<!-- Apply to all three scripts in this plan, and (per plan 09-04) to agriculture too. -->

CLI, uniform across all five chart scripts, modelled on
`compute_protected_area_coverage.py::main()` lines 137-175:
  `--ll <slug>` computes and writes only that Living Lab; the default is all five.
  `--dry-run` prints the computed series to stdout and writes no file.
  Slugs come from `data/ll_boundaries.geojson`'s `ll_slug` property, never hardcoded.
  An unknown `--ll` value raises a RuntimeError listing the available slugs.

Series ordering: sort by `pct` descending, tie-broken by `label["en"]` ascending. This is
deterministic (so re-running produces no git churn beyond `generated_at`) and puts the
dominant category first for a future chart consumer.

Rounding: `pct` to 1 decimal; `value` to 1 decimal for hectare quantities and a plain
integer for counts.

Never drop a row: every observed category becomes a series entry. If a grouping column
holds a null, the script raises rather than letting pandas' default `groupby` silently
discard those rows.

Output path: always `get_layer(<dataset id>)["output"]["chart_pattern"].format(slug=slug)`
resolved through `resolve()`. Never a hardcoded literal path.

Writing: always via `write_bar_chart`. No script in this plan may call `json.dumps`.
</shared_conventions>
