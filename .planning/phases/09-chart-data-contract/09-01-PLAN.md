<objective>
Establish the chart JSON contract as executable code plus prose documentation, before any
layer-specific chart script exists.

Purpose: CHARTS-01 locks a chart_type-discriminated schema with two variants sharing one
envelope. If each of the five chart scripts writes its own `json.dumps(...)` call, the
envelope will drift across layers within one phase. Extracting one writer module first
makes the schema physically impossible to get wrong in the four downstream plans, and
satisfies CLAUDE.md's `sort_keys=True` rule in exactly one place.

Output: `data-pipeline/python/chart_contract.py` (the writer module every chart script
imports) and the `## Chart data contract` section in `data-pipeline/README.md`.
</objective>

Module: data-pipeline/python/chart_contract.py

  write_bar_chart(*, output_path: Path, ll_slug: str, layer_id: str, unit: dict,
                  series: list[dict], source: str, mock: bool = False) -> None

  write_line_chart(*, output_path: Path, ll_slug: str, layer_id: str, unit: dict,
                   x_axis: list[dict], lines: list[dict], source: str,
                   mock: bool = False) -> None

Envelope keys written by BOTH functions (D-01):
  ll_slug, layer_id, chart_type, unit, mock, source, generated_at
Data-carrying keys:
  bar  -> series   : [{label: {en, de}, value: number, pct: number}]
  line -> x_axis   : [{key: str, label: {en, de}}]
          lines    : [{label: {en, de}, points: [{x: str, value: number}]}]

Envelope field semantics (locked):
  layer_id     = the sources.yaml `app_layer` value (agriculture|landscape|soil|economic|climate)  -- D-13
  source       = the sources.yaml dataset `id` (landuse-croptypes|io-lulc-landcover|buek250|boris|chelsa-climate) -- D-04
  mock         = false for every file this phase commits (D-02)
  generated_at = UTC ISO-8601 with a trailing Z
  value        = raw absolute quantity (ha, or zone count for economic) -- D-14
  pct          = percentage share of the per-LL total -- D-14
</interfaces>

    holding `x_axis`, and vice versa.

    `generated_at` is computed inside each function as
    `datetime.now(timezone.utc).isoformat().replace("+00:00", "Z")` — never passed in by a
    caller, so 25 files written across three plans all use one timestamp idiom.

    chart_type-discriminated schema; `chart_type` remains an open string at the schema
    level (D-01) but only these two values have producers after Phase 9; and that no chart
    script may call `json.dumps` directly.

    Do not add validation of `series`/`lines` contents — shape enforcement lives in
    plan 09-06's pytest contract tests, not in the writer (the writer stays a thin,
    dependency-free stdlib module so any future chart script can import it cheaply).
