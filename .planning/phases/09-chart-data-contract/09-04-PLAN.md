<objective>
Build the one chart that requires genuinely new pipeline logic: a per-Living-Lab crop-type
histogram over the national `landuse-croptypes` raster.

Purpose: `landuse-croptypes` is the only raster layer in this project built nationally
(`output.pmtiles`, no `pmtiles_pattern`), so unlike land cover there is no existing per-LL
pixel histogram to reshape. CHARTS-03 therefore needs a real clip-and-count pass over a
481 MB GeoTIFF. Isolating it in its own plan keeps that heavier, riskier work away from the
three cheap charts in plan 09-03 and gives it a dry-run gate on the smallest Living Lab
before the full five-Living-Lab run.

Output: `data-pipeline/python/compute_agriculture_chart.py` and five committed
`data/charts/landuse-croptypes-*.json` files.
</objective>

<shared_conventions>
<!-- Identical to plan 09-03's shared_conventions block; restated so this plan is
     self-contained for a parallel executor. -->

CLI, uniform across all five chart scripts, modelled on
`compute_protected_area_coverage.py::main()` lines 137-175:
  `--ll <slug>` computes and writes only that Living Lab; the default is all five.
  `--dry-run` prints the computed series to stdout and writes no file.
  Slugs come from `data/ll_boundaries.geojson`'s `ll_slug` property, never hardcoded.
  An unknown `--ll` value raises a RuntimeError listing the available slugs.

Series ordering: sort by `pct` descending, tie-broken by `label["en"]` ascending.

Rounding: `pct` to 1 decimal; hectare `value` to 1 decimal.

Never drop a row: every observed non-nodata class becomes a series entry.

Output path: always `get_layer("landuse-croptypes")["output"]["chart_pattern"].format(slug=slug)`
resolved through `resolve()`. Never a hardcoded literal path.

Writing: always via `write_bar_chart`. This script may not call `json.dumps`.
</shared_conventions>

    Structure it as: `get_layer("landuse-croptypes")`, then `ensure_input_available(layer)`

    that single national file. This is the one structural difference from
    `build_land_cover.py`, which loops a `input.tiles` slug-to-tile map - crop types has a
    single `input.path`, so there is no tile-selection step and no `_tile_shim` equivalent.

    Per slug: call `build_clip_geometry(layer, src.crs, slug=slug)` - imported from
    `build_pmtiles`, never re-derived - then `rasterio.mask.mask(src,
    [clip_geom.__geo_interface__], crop=True, all_touched=True, nodata=src.nodata)`, then
    `np.unique(clipped[0], return_counts=True)` to build a `{class_value: pixel_count}`
    histogram. Drop class value 0 (`input.nodata`). Do not reproject, do not build a
    colormap, do not write any GeoTIFF or MBTiles - this script produces one JSON per
    Living Lab and nothing else.

    Convert pixel counts to hectares using the layer's own `input.resolution_m` (a 10 m
    pixel is 100 m2, so the factor is `resolution_m * resolution_m / 10000`); read
    `resolution_m` from `sources.yaml` rather than writing the factor as a bare literal.
    The percentage denominator is the sum of non-nodata pixels, so `pct` is a share of
    mapped crop area within the clip, not of total Living Lab area.

    Labels come from the layer's 19-row `legend` list, matched on `int(entry["value"])`;
    pass each legend entry's `label` object through unchanged as the series `label`. Do not
    copy the legend `color` - the locked bar entry is exactly `{label, value, pct}`.
