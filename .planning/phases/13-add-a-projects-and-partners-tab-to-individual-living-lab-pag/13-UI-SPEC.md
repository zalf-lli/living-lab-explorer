# Phase 13 — UI Design Contract
## Add a Partners & Projects tab to individual Living Lab pages

> Visual and interaction contract for the new "Partners & Projects" tab: a right-side-separated tab
> control, a boundary-only Leaflet map with partner point markers, and a two-section overview panel
> (Partners / Projects). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Locked by `13-CONTEXT.md` (do not re-decide):** exact bilingual tab labels (D-01/D-02), two
visually separate sections (D-03), right-side tab placement (D-04), one combined tab (D-05),
separate hand-authored JSON grouped by slug (D-06/D-07), sync.py publish pattern (D-08), lazy
fetch only when active (D-09), partners-only map markers (D-10), no permission filtering (D-11),
hover/focus tooltip + click-to-website (D-12), boundary-only map background (D-13), coordinate-less
partners stay list-only (D-14), partner/project field sets (D-15/D-16), bilingual scope limited to
project summaries (D-17), quiet empty states (D-18). This document specifies what those decisions
left open: exact component names, marker styling, panel density, copywriting, and schema key names.

**Pre-populated from:** `13-CONTEXT.md` (D-01..D-18, all locked), `13-RESEARCH.md` (component tree,
file responsibilities, `LLMap` extraction plan, Leaflet marker/tooltip findings), and direct

## Layout & Composition

### Right-side tab group (D-04)

`LayerTabs.jsx` currently renders one `<div style={{display:'flex', gap:0, ...}}>` that `.map()`s
over the 5-entry `LAYERS` array. The Partners & Projects tab becomes a **second, visually distinct
group** in the same row, not a 6th pill appended to that list:

```jsx
export function LayerTabs({ active, onChange, variant = 'light' }) {
  const { t } = useTranslation()
  const isDark = variant === 'dark'
  return (
    <div
      style={{
        display: 'flex',
        justifyContent: 'space-between',
        alignItems: 'flex-end',
        borderBottom: `2px solid ${isDark ? 'rgba(131,210,175,0.25)' : C.surfaceMid}`,
      }}
    >
      <div style={{ display: 'flex', gap: 0 }}>
        {LAYERS.map((l) => /* existing tab button, unchanged */)}
      </div>
      <button
        onClick={() => onChange('partners')}
        style={{
          padding: '9px 16px',
          border: 'none',
          background: 'none',
          cursor: 'pointer',
          fontSize: 13,
          fontWeight: active === 'partners' ? 700 : 500,
          color: active === 'partners'
            ? (isDark ? C.lime : C.teal)
            : (isDark ? 'rgba(255,255,255,0.55)' : 'rgba(2,35,34,0.5)'),
          borderBottom: active === 'partners'
            ? `2.5px solid ${isDark ? C.lime : C.teal}`
            : '2.5px solid transparent',
          borderLeft: `1px solid ${isDark ? 'rgba(255,255,255,0.2)' : C.mutedLight}`,
          marginBottom: -2,
          marginLeft: 8,
          paddingLeft: 16,
          transition: 'all 0.15s',
          whiteSpace: 'nowrap',
        }}
      >
        {t('layers.partners')}
      </button>
    </div>
  )
}
```

`justifyContent: 'space-between'` pushes the new button to the far right of the tab row (both
`LayoutSplit`'s narrow sidebar strip and `LayoutStacked`'s full-width strip already give this row
enough horizontal room — confirmed against both call sites). The `borderLeft` + `marginLeft: 8` +
`paddingLeft: 16` combination is the "visually separated, not appended inline" signal D-04
requires: an 8px gap plus a hairline divider reads as a second group at a glance, reusing the exact
divider treatment `LayoutSplit`'s sidebar already uses between its own stacked sections
(`borderRight: 1.5px solid C.mutedLight`), just rotated to a left border. **Do not** add `partners`
to the `LAYERS` array in `layers.js` — it must never appear in `.map(LAYERS...)` (see Data
`layers.js` change below).

`t('llDetail.layerTabsHint')` ("Click the tabs to explore different socio-environmental features.")
is **suppressed when `active === 'partners'`** — that copy describes the 5 thematic map layers and
would misdescribe a partner/project overview tab. No replacement hint copy is shown; the panel's own
section headings are self-explanatory (matches D-18's "quiet" tone).

### Three `LLDetail.jsx` branch points (mirrors Phase 12's `DownloadReportCTA` precedent, but this
### phase branches the whole content area, not just one control)

Per `13-RESEARCH.md` Pitfall 1, `LLDetail.jsx` composes the map/stat/chart/text stack independently
in three places that must **all** branch together:

1. **`LayoutSplit`** (sidebar/map split layout) — right column currently renders
   `StatPanel` → chart card → text-block card → `CompareCTA`/`DownloadReportCTA` row unconditionally.
2. **`LayoutStacked`** (full-width stacked layout) — same four blocks, unconditionally.
3. **`ComparisonColumn`** (used inside two-column comparison mode) — compact variant of the same four
   blocks, unconditionally.

**Locked pattern for all three:** wrap the existing per-layout content block (everything between the
layer tabs row and the `CompareCTA`/`DownloadReportCTA` row — the header block, badge, and those two
final controls stay unconditional in every layout) in a ternary:

```jsx
{layer === 'partners'
  ? <PartnersProjectsTab ll={ll} />
  : (/* existing StatPanel + chart card + text-block card, unchanged */)}
```

`PartnersProjectsTab` receives only `ll` — no `layer`, `climateVariable`, `period`, etc. props are
threaded through, since none of the climate/raster machinery applies. It renders its own internal
map+panel layout (see below) that adapts to whichever layout container it's placed inside via
`width: '100%'` — it does not need a `compact` prop; `PartnersOverviewPanel`'s card padding is
already dense enough to read correctly at `ComparisonColumn`'s narrower width (see Spacing Scale).

**Included in comparison mode, deliberately, not special-cased** (resolves `13-RESEARCH.md`'s Open
Question 1): the Partners & Projects tab is selectable during `?compare=` mode exactly like every
other tab, rendering independently inside each `ComparisonColumn`. This is the simpler, more
consistent behavior and requires no new gating logic — `LayerTabs` is already shared across both
columns (Phase 10 D-07), so `layer` reaching `'partners'` there is expected, not a special case to
suppress.

### `PartnersProjectsTab` internal layout

```
┌─────────────────────────────────────────┐
│  PartnersMap (height: 300, same as       │
│  LLMap's height in LayoutStacked/         │
│  ComparisonColumn; LayoutSplit's map      │
│  column keeps its own 100%-height slot)   │
├─────────────────────────────────────────┤
│  PartnersOverviewPanel                    │
│    ├─ "Partners" section heading          │
│    ├─ partner cards (grid) OR empty state │
│    ├─ "Projects" section heading          │
│    └─ project cards (list) OR empty state │
└─────────────────────────────────────────┘
```

Single vertical stack, map on top, panel below — in **every** layout (`LayoutSplit`,
`LayoutStacked`, `ComparisonColumn`), unlike the thematic tabs which place the map beside the panel
in `LayoutSplit`'s 42/58 grid. This is a deliberate simplification: `LayoutSplit`'s left column is a
narrow 42% sidebar sized for a tall map plus `LayerTabs`, not for two-section list content with
potentially many partner/project cards — stacking avoids squeezing card text into a narrow column.
`gap: 24px` (`lg` token) between the map and the panel.

**Visual anchor:** the map is the primary visual anchor for this screen — it renders first,
full-width, at the top of the stack, and establishes the Living Lab's geographic context (boundary +
partner locations) before any text. `PartnersOverviewPanel` is secondary: read top-to-bottom below
the map as supporting detail once that geographic context is set, not competing with it for
attention.

## `PartnersMap` Component

### Boundary + basemap (D-13)

Reuses the extracted `selectBoundary`/`getBounds` from `app/src/lib/llBoundary.js` and the existing
exported `buildMaskFeature` from `app/src/lib/buildMaskGeometry.js` — **identical** boundary-fit and
outside-boundary-dim behavior to every other tab's map, with zero raster/vector thematic layer and
zero `MapLegend`:

```jsx
<MapContainer bounds={bounds} boundsOptions={{ padding: [16, 16] }} scrollWheelZoom style={MAP_STYLE}>
  <TileLayer
    maxZoom={19}
    subdomains={['a', 'b', 'c', 'd']}
    url="https://{s}.basemaps.cartocdn.com/rastertiles/voyager/{z}/{x}/{y}{r}.png"
  />
  {maskFeature ? <GeoJSON data={maskFeature} style={MASK_STYLE} /> : null}
  <GeoJSON data={boundaryFeature} style={{ color: ll.outlineColor || C.orange, weight: 2.5, fill: false }} />
  {partnersWithCoords.map((p) => <PartnerMarker key={p.id ?? p.name} partner={p} />)}
</MapContainer>
```

Same tile URL, same subdomains, same `MASK_STYLE` fill (`#ffffff` @ 0.6 opacity, non-interactive) as
`LLMap` — copied literals, not imports, since those two constants are module-private to
`LLMap/index.jsx` and are trivial one-line values (not worth a second extraction; unlike
`selectBoundary`/`getBounds`, which are real logic).

**Attribution — one deliberate departure from `LLMap`:** `PartnersMap` does **not** set
`attributionControl={false}` and does **not** port `LLMap`'s custom `MapInfoControl` (which is
module-private and whose "show layer/overlay source" logic has nothing to show here per D-13).
It keeps Leaflet's own default attribution control (small grey "Leaflet | © OpenStreetMap
contributors" text, bottom-right, from the already-globally-imported `leaflet/dist/leaflet.css`).
This satisfies the OSM/CARTO attribution requirement with zero new code and zero private-code
extraction, appropriate for a map whose only content is the base tiles, the boundary line, and
partner markers.

**No `MapLegend`, no legend bar under the map** (D-13 — "do not render a thematic legend").

### Partner markers (D-10, D-12, D-14)

`react-leaflet`'s declarative `<Marker>`/`<Tooltip>` (v5.0.0, already installed — see
`13-RESEARCH.md` Standard Stack). **Not** `<CircleMarker>` and **not** Leaflet's default icon image
— a custom `L.divIcon` sidesteps the well-known Vite+Leaflet default-marker-icon bundling issue and
gives full inline-style control consistent with the rest of this codebase's zero-icon-asset
convention.

```jsx
import L from 'leaflet'

const PARTNER_ICON = L.divIcon({
  className: 'partner-marker', // must be a real class, not '' — Leaflet's default
                                 // .leaflet-div-icon CSS sets a white background + grey
                                 // border on any divIcon with the default class; this
                                 // custom class must reset both to transparent/none so
                                 // only the inline-styled circle below is visible
  html: '<span style="display:block;width:100%;height:100%;border-radius:50%;background:#eb5b25;border:2px solid #ffffff;box-shadow:0 1px 4px rgba(2,35,34,0.35);"></span>',
  iconSize: [18, 18],
  iconAnchor: [9, 9],
})

function PartnerMarker({ partner }) {
  const { t } = useTranslation()
  return (
    <Marker
      position={[partner.lat, partner.lng]}
      icon={PARTNER_ICON}
      keyboard
      eventHandlers={{
        focus: (e) => e.target.openTooltip(),
        blur: (e) => e.target.closeTooltip(),
        click: () => {
          if (partner.website) window.open(partner.website, '_blank', 'noopener,noreferrer')
        },
      }}
      alt={partner.website ? t('partnersTab.markerAria', { name: partner.name }) : partner.name}
    >
      <Tooltip direction="top" offset={[0, -12]}>{partner.name}</Tooltip>
    </Marker>
  )
}
```

- `18px` diameter, `C.orange` fill, `2px` white border — the single accent color reserved for this
  interactive point (see Color below). Deliberately smaller and simpler than the app's other
  point-like affordance (`✉` `ContactManagerButton` pill) because there can be many of these on one
  map; a large or textual marker would clutter small Living Labs' boundaries.
- `keyboard` explicit prop (Leaflet's own default, made explicit here rather than relied-upon) plus
  the `focus`/`blur` → `openTooltip`/`closeTooltip` `eventHandlers` wiring is the locked answer to
  D-12's "hover/focus" requirement and `13-RESEARCH.md` Pitfall 4's cited Leaflet gap (tooltips are
  hover-only by default; this is the standard community workaround, not an official-docs guarantee —
  flag for a manual keyboard-only pass at the phase's human-verify checkpoint).
- **Click behavior (D-12):** opens `partner.website` in a new tab via `window.open(url, '_blank',
  'noopener,noreferrer')` when present; **does nothing** (no-op, no error, no toast) when absent —
  matching this codebase's fail-quiet convention (Phase 12's `DownloadReportCTA` "no visible error
  UI" precedent). No `cursor: pointer` CSS override is needed — Leaflet already sets `cursor: pointer`
  on interactive markers by default.
- **Partners without coordinates (D-14) never reach `<PartnerMarker>` at all** — filtered out in
  `PartnersProjectsTab` before the array reaches `PartnersMap` (`partner.lat != null && partner.lng
  != null`), not filtered inside the map component. This keeps the "has coordinates?" branch in one
  place, matching `13-RESEARCH.md`'s Component Responsibilities table.
- **Tooltip text is the partner's raw `name` field** (no i18n key — D-17 confirms partner names are
  shared, non-bilingual strings). Font size/weight inherited from Leaflet's own default tooltip CSS
  (12px) plus this component's own `fontWeight: 700` wrapper — see Typography below.

## `PartnersOverviewPanel` Component

### Section structure (D-03)

Two independent `<section>` blocks, always both rendered, always both visible (D-18 — never
collapsed away even when empty):

```jsx
<div style={{ display: 'flex', flexDirection: 'column', gap: 24 }}>
  <PartnersSection partners={partners} />
  <ProjectsSection projects={projects} lang={lang} />
</div>
```

### Section heading (shared style, reuses the existing card-eyebrow pattern)

Both section headings reuse the exact "distribution/projection title" eyebrow style already used
above every `BarChart`/`LineChart` card in `LLDetail.jsx` (`fontSize: 11, fontWeight: 700, color:
C.greenMid, textTransform: 'uppercase', letterSpacing: '0.1em'`) — no new heading style is invented:

```jsx
<div style={{ fontSize: 11, fontWeight: 700, color: C.greenMid, textTransform: 'uppercase', letterSpacing: '0.1em', marginBottom: 8 }}>
  {t('partnersTab.partnersHeading')}
</div>
```

### Partner cards (grid)

```jsx
<div style={{ display: 'grid', gridTemplateColumns: 'repeat(auto-fill, minmax(220px, 1fr))', gap: 8 }}>
  {partners.map((p) => <PartnerCard key={p.id ?? p.name} partner={p} />)}
</div>
```

`repeat(auto-fill, minmax(220px, 1fr))` — a responsive card grid (not a fixed 2/3/4-column count)
because partner counts vary per Living Lab and this component must read correctly at both
`LayoutStacked`'s full page width and `ComparisonColumn`'s roughly-half-page width without a
`maxColumns`-style prop (unlike `StatPanel`, whose fixed-count KPI grid genuinely needs one).

Each `PartnerCard`:

```jsx
<div style={{ background: C.white, borderRadius: 8, padding: '8px 16px', border: `1px solid ${C.mutedLight}` }}>
  <div style={{ fontSize: 14, fontWeight: 700, color: C.teal, lineHeight: 1.3 }}>{partner.name}</div>
  {partner.type ? (
    <div style={{ fontSize: 12, fontWeight: 400, color: C.greenMid, lineHeight: 1.4, marginTop: 4 }}>{partner.type}</div>
  ) : null}
  {partner.location ? (
    <div style={{ fontSize: 12, fontWeight: 400, color: C.muted, lineHeight: 1.4, marginTop: 4 }}>{partner.location}</div>
  ) : null}
  {partner.website ? (
    <a href={partner.website} target="_blank" rel="noopener noreferrer"
       style={{ display: 'inline-block', fontSize: 12, fontWeight: 700, color: C.orange, textDecoration: 'none', marginTop: 8 }}>
      {t('partnersTab.visitWebsite')} <span aria-hidden="true">↗</span>
    </a>
  ) : null}
</div>
```

Card chrome (`border: 1px solid C.mutedLight`, `borderRadius: 8`, `background: C.white`) matches
`StatPanel`'s own KPI tile — the established "small data card" visual language in this codebase,
reused rather than reinvented — with padding set to `'8px 16px'` rather than `StatPanel`'s own
`'12px 16px'`: `StatPanel`'s literal predates this project's 4/8/16/24/32/48/64 spacing-grid
convention and is not copied verbatim here, so every dimension in this card lands exactly on the
grid. `↗` is `aria-hidden` (matches `ContactManagerButton`'s `<span aria-hidden="true">✉</span>`
pattern) — the visible link text already announces the action.

### Project list

Projects render as a vertical list, not a grid (project summaries are longer-form text than partner
metadata, so a single column reads better):

```jsx
<div style={{ display: 'flex', flexDirection: 'column', gap: 8 }}>
  {projects.map((p) => <ProjectCard key={p.id ?? p.title} project={p} lang={lang} />)}
</div>
```

Each `ProjectCard`:

```jsx
<div style={{ background: C.white, borderRadius: 8, padding: '8px 16px', border: `1px solid ${C.mutedLight}` }}>
  <div style={{ fontSize: 14, fontWeight: 700, color: C.teal, lineHeight: 1.3 }}>{project.title}</div>
  {project.summary?.[lang] ? (
    <div style={{ fontSize: 12, fontWeight: 400, color: C.muted, lineHeight: 1.4, marginTop: 4 }}>{project.summary[lang]}</div>
  ) : null}
  <div style={{ display: 'flex', alignItems: 'center', gap: 8, marginTop: 8, flexWrap: 'wrap' }}>
    {project.partner ? (
      <span style={{ fontSize: 12, fontWeight: 400, color: C.greenMid, lineHeight: 1.2 }}>
        {t('partnersTab.projectPartnerLabel')} {project.partner}
      </span>
    ) : null}
    {project.website ? (
      <a href={project.website} target="_blank" rel="noopener noreferrer"
         style={{ fontSize: 12, fontWeight: 700, color: C.orange, textDecoration: 'none' }}>
        {t('partnersTab.visitWebsite')} <span aria-hidden="true">↗</span>
      </a>
    ) : null}
  </div>
</div>
```

`project.summary[lang]` uses `normalizeLanguage(i18n.resolvedLanguage)` (imported from `app/src/i18n.js`
— per `13-RESEARCH.md` Pitfall 5, the more central of the two existing language-normalization idioms,
not a third ad hoc ternary) resolved once in `PartnersProjectsTab` and passed down as a plain `lang`
prop, not recomputed in every card.

**`project.partner` renders as a plain display string** (resolves CONTEXT's "plain string vs. stable
id" discretion item): the schema stores the partner's name directly on the project entry rather than
a foreign-key id resolved against the partners array at render time. This keeps `ProjectCard`
self-contained (no lookup into the sibling `partners` array needed) and matches D-17's framing that
partner names are themselves shared, non-bilingual strings — the same string authored once on the
partner entry is simply re-typed on the project entry. Authoring cost (keeping the two copies in
sync by hand) is accepted given the "exemplar projects" scale this phase targets (tens of entries,
not hundreds — per `13-RESEARCH.md` Assumption A3).

### Empty states (D-18)

Both sections render their own quiet empty state, in place of the card grid/list, when their array
is empty — **the section itself stays visible** (heading + empty state), never collapsed away:

```jsx
{partners.length === 0 ? (
  <div style={{ background: C.white, borderRadius: 8, padding: '8px 16px', border: `1px dashed ${C.mutedLight}` }}>
    <div style={{ fontSize: 12, fontWeight: 400, color: C.muted, lineHeight: 1.4 }}>
      {t('partnersTab.partnersEmpty')}
    </div>
  </div>
) : ( /* card grid */ )}
```

**Dashed border** (`1px dashed C.mutedLight`, vs. cards' `1px solid`) is the deliberate visual
signal that this is an absence-of-content placeholder, not a populated tile — the same
dashed-vs-solid semantic Phase 12's `DownloadReportCTA` UI-SPEC already established for this
codebase ("dashed borders are this app's existing signal for an add/not-yet-configured affordance").
No heading/body two-line structure here (unlike `StatPanel`'s empty state) — a single sentence is
enough for a quiet placeholder per D-18's "short" requirement.

## Spacing Scale

Declared values (all multiples of 4px, drawn from the app-wide 4/8/16/24/32/48/64 set):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Partner/project card meta-line top margins (`type`, `location`, project `summary` rows) |
| sm | 8px | Section heading bottom margin; tab-group divider `marginLeft`; partner card grid `gap`; project list `gap`; card vertical padding (top/bottom); "Visit website" link top margin; project card meta-row `gap` and top margin |
| md | 16px | Partner/project card padding (horizontal); right-side tab `paddingLeft` |
| lg | 24px | Map-to-panel gap; Partners-section-to-Projects-section gap |

**Exceptions (four, all named and justified — see below):**

1. The marker's `2px` border is a visual-weight value (matches Leaflet's own default marker border
   thickness convention, and halving it to a nominal "1px" would read as a hairline, not a filled
   dot) rather than a spacing/layout dimension, so it is exempted from the 4px-grid rule the same way
   `DownloadReportCTA`'s button-radius rounding exercise (Phase 12 UI-SPEC) treated icon-scale
   details as a separate concern from layout spacing.
2. The new right-side tab button's own `padding: '9px 16px'` shorthand (see the `LayerTabs.jsx` JSX
   sample above) is inherited **verbatim** from the existing thematic tab pill's own `padding: '9px
   16px'` in `app/src/components/LayerTabs.jsx` line 23 — it is not a new or independently-chosen
   value. It is copied as-is specifically to preserve pixel-exact vertical alignment between the new
   button and the 5 existing tab pills sharing the same tab-strip row: rounding it down to a
   grid-exact `8px 16px` would shift the new button's baseline by 1px relative to the tabs it sits
   beside in the same row, reintroducing the exact visual misalignment the shared-row layout (D-04)
   is designed to avoid. It is exempted from the 4px grid the same way the marker border above is
   exempted, for the same category of reason: matching an existing, already-shipped pixel value
   takes priority over strict grid conformance for this one non-layout dimension. The button's other
   dimensions — `marginLeft: 8`, `paddingLeft: 16` — are new values introduced by this phase and are
   both grid-exact, not exceptions.
3. The new right-side tab button's own `marginBottom: -2` (see the `LayerTabs.jsx` JSX sample above)
   is inherited **verbatim** from the existing thematic tab pill's own `marginBottom: -2` in
   `app/src/components/LayerTabs.jsx` line 39 — it is not a new or independently-chosen value, and
   like exception 2 it exists to preserve pixel-exact alignment rather than to express spacing. All
   6 tab buttons (5 existing thematic pills plus this new one) share the same row and the same
   `2px solid` `borderBottom` on their parent `<div>`; each button's own `2.5px` active/transparent
   `borderBottom` sits half a pixel proud of that parent border, and `marginBottom: -2` is the
   existing, already-shipped correction that pulls each button's underline back up so it renders
   flush with the parent divider instead of appearing as a doubled or offset line. Copying this
   value onto the new button keeps its underline pixel-aligned with the other 5 tabs' underlines,
   which all share that same `border-bottom` row — rounding it to a grid-exact `0` would reintroduce
   a visible seam between the new button and its neighbors, the same category of regression
   exception 2 is written to avoid.
4. The loading-state block's own `padding: 40` (see the Interaction States table below,
   `usePartnersProjects` loading row) is inherited **verbatim** from this codebase's existing
   `LoadingCard` component in `app/src/pages/LLDetail.jsx` line 1234
   (`padding: 40, color: C.muted, fontSize: 14, display: 'flex', justifyContent: 'center'`) — the
   identical `padding: 40` value is also used for the same "full-bleed centered temporary status
   message" purpose in `app/src/App.jsx` line 48's `ErrorBanner` (`padding: 40, color: '#bb3f11',
   fontSize: 14`), confirming this is an established two-call-site pattern in the codebase, not a
   one-off. It is not a new or independently-chosen value: this phase's loading/error slot
   deliberately reuses that exact existing treatment (rather than inventing a grid-rounded `32px` or
   `48px` variant) so a lazily-mounted tab's temporary status message reads identically to every
   other "loading/error takes over this slot" moment already shipped in the app. It is exempted from
   the 4px grid the same way exceptions 2 and 3 are: matching an existing, already-shipped pixel
   value across multiple call sites takes priority over strict grid conformance for this one reused
   treatment.

Every other dimension in this document — including every JSX code sample above — lands exactly on
the 4/8/16/24/32/48/64 grid (this includes the unmodified `gap: 0` on the existing thematic-tabs
wrapper `<div>`, `0` being trivially a multiple of 4). There are now four named, justified exceptions
(marker border, tab-button padding, tab-button `marginBottom`, loading/error block padding) and zero
unexplained off-grid literals left for the executor to resolve. This conclusion is the result of a
full end-to-end re-read of every `margin*`/`padding*`/`gap`/`rowGap`/`columnGap`/`top`/`left`/`right`/
`bottom` literal in this document (including every number inside every shorthand string), cross-
checked against the actual shipped source in `app/src/components/LayerTabs.jsx`,
`app/src/pages/LLDetail.jsx`, `app/src/components/StatPanel.jsx`, `app/src/App.jsx`, and
`app/src/components/ContactManagerButton.jsx` — not a targeted fix of a single previously-reported
value.

## Accessibility

- Marker `alt` text (rendered as the underlying `<img>`/icon element's accessible name via
  react-leaflet's `Marker` `alt` prop) is `t('partnersTab.markerAria', { name: partner.name })` when
  a website exists, or the bare partner name otherwise — screen readers announce which partner's
  website a given marker opens, not just "marker."
- `keyboard` explicitly set `true` on every `<Marker>` (Leaflet's own default, made explicit for
  clarity) so every marker is reachable via Tab in boundary-crossing DOM order alongside the
  overview panel's own links.
- No `outline: none` anywhere in this phase's new components (matches the codebase's one
  non-negotiable baseline accessibility rule, per Phase 12's UI-SPEC).
- External links (`<a target="_blank" rel="noopener noreferrer">` in the overview panel, `window.open(...,
  'noopener,noreferrer')` on marker click) follow the codebase-wide safe-external-link convention
  exactly.
- The `↗` glyph is wrapped `<span aria-hidden="true">↗</span>` in both card link instances — visible
  link text alone ("Visit website") already carries the full meaning.
- Empty-state placeholders are plain text, not `role="alert"` — they describe steady-state absence
  of content, not a transient error, so no ARIA live-region behavior is needed (consistent with
  `StatPanel`'s own empty-state precedent, which uses a plain `<div>`).

## Data Schema (UI-facing key names — resolves CONTEXT's schema-key discretion item)

This is the schema the components above are written against; it is not a substitute for the
planner's own data-contract task, but every field name below is load-bearing for the JSX in this
document and should not be silently renamed downstream without updating this contract.

```jsonc
// data/partners_projects.json (hand-authored, D-06/D-07/D-08)
{
  "<ll-slug>": {
    "partners": [
      {
        "id": "optional-stable-slug",       // optional; falls back to `name` as the React key
        "name": "Partner display name",     // shared string, D-17 — required
        "type": "Research institution",     // shared string, D-15 — optional, free text (no enum, no i18n)
        "location": "Berlin, DE",           // shared string, D-15 — optional, free text
        "website": "https://example.org",   // shared URL string, D-17 — optional
        "lat": 52.52,                       // number, optional — D-14: absent => list-only, no marker
        "lng": 13.405                       // number, optional — D-14: absent => list-only, no marker
      }
    ],
    "projects": [
      {
        "id": "optional-stable-slug",
        "title": "Project title",           // shared string, D-16 — required
        "summary": { "en": "...", "de": "..." }, // bilingual, D-17 — optional, `{en,de}` shape matches
                                                   // ll_content.json's existing narrative fields
        "partner": "Partner display name",  // plain string, matches a partners[].name value — NOT an id
        "website": "https://example.org"    // shared URL string, D-17 — optional
      }
    ]
  }
}
```

**Locked recommendations (resolve CONTEXT's remaining discretion items):**
- Flat `lat`/`lng` numeric fields, not a nested `coordinates` array — human-authoring-friendly and
  avoids GeoJSON `[lng, lat]` axis-order mistakes in a hand-typed file (this file has no other
  GeoJSON precedent to match, unlike `data/geojson/*.geojson`).
- `project.partner` is a **plain display string**, not a foreign-key id (see `ProjectCard` above for
  the full rationale).
- Every Living Lab slug key must exist in the file, even with empty `partners`/`projects` arrays
  (per `13-RESEARCH.md` Pitfall 3 — `sync.py`'s `STATIC_DATA_FILES` copy has no missing-file
  fallback, so the file itself must exist and be committed before `sync.py`'s edit lands, and every
  slug must resolve to *something* so `usePartnersProjects` never needs a "missing slug" branch
  distinct from "empty arrays").
