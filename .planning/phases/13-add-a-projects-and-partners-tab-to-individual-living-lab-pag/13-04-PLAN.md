<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hand-authored JSON → panel DOM | Partner/project name, type, location, summary and website values render into text nodes and link hrefs |
| in-app link → external origin | `target="_blank"` navigations hand control to third-party sites |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | `PartnerCard` / `ProjectCard` `href` | mitigate | Every `href` is the return value of `safeExternalUrl(...)`, and the link element is not rendered at all when it returns `null` — a `javascript:`/`data:` URL in the JSON can never become a live href |
| T-13-02 | Information Disclosure | External `<a target="_blank">` | mitigate | Every external anchor carries `rel="noopener noreferrer"`, matching the convention already enforced in `ContactManagerButton`, `DownloadReportCTA` and `StatPanel` |
| T-13-03 | Tampering (XSS) | Text rendering of authored content | mitigate | All authored strings render as React children (auto-escaped); this file uses no `dangerouslySetInnerHTML` — asserted by lint plus the whole-phase negative grep in plan 13-06 Task 1's phase gate |
| T-13-10 | Repudiation | Project-to-partner association | accept | `project.partner` is a plain display string with no referential integrity check by design (13-UI-SPEC locked rationale); the authoring scale is tens of entries and drift is caught by human review of the committed JSON |
| T-13-SC | Tampering | npm installs | mitigate | Zero new packages; `app/package.json` must be unchanged by this plan |
</threat_model>
