| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Testing a worktree-agent's fix in the wrong checkout | The human reported "no change, map still on the right" after a fix was committed — the fix only existed on the executor's isolated worktree branch, never merged into the primary checkout the human was running `npm run dev` from. | advisory | When a worktree-isolated executor reports a fix, merge the worktree branch into the primary branch BEFORE asking the human to re-verify, not after. Confirm with `git log --oneline -3` on the primary checkout's HEAD that the fix commit is actually present. |
| Running pytest with the wrong Python interpreter | `python -m pytest` initially reported a spurious `ModuleNotFoundError: No module named 'rasterio'` failure because it resolved to system Python (Windows Store shim), not the project's `data-pipeline/.venv`. Looked like a real regression at first. | advisory | Always invoke `"data-pipeline/.venv/Scripts/python.exe" -m pytest ...` explicitly on this project, per CLAUDE.md's Windows/Python 3.12 requirement — never bare `python`. |
