# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this phase's UI surface:** the Climate tab's map slot (`app/src/data/layers.js:41`, currently
`{ id: 'climate', type: 'placeholder' }`) becomes a real raster layer with two new controls (variable
picker, period switcher), and its two null-forever KPI tiles (`agr_ch4_kt`/`agr_n2o_kt`) are replaced by
four CHELSA-derived tiles with a new two-line shape. No new route, no new tab, no new page.

**Visual hierarchy / primary focal point:** the raster map is the primary focal point — it occupies the
largest area and is what the eye lands on first, exactly as on every other tab. The variable picker and
period switcher are secondary controls (they sit directly above/beside the map and exist only to change
what the map shows). The four KPI tiles are tertiary — a confirming, at-a-glance numeric summary below the
map, read after the map, never before it. This ordering is unchanged from every prior tab (map first, stats
second) and Phase 8 introduces no new page region that would compete with it.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled inline-style React components (`style={{...}}` objects, no CSS-in-JS library) |
| Icon library | none — inline hand-authored SVG paths only (see `app/src/data/ll_icons.js`); no new icons are needed for this phase |

**Why `Tool: none`:** `CLAUDE.md` and `REQUIREMENTS.md`'s Out of Scope list explicitly forbid a Tailwind /
CSS-framework migration ("inline-style-with-theme pattern stays"), and shadcn requires Tailwind. No
`components.json`, `tailwind.config.*`, or `postcss.config.*` exist anywhere in the repo (verified). Seven
prior phases (1, 2.1, 2.2, 4, 5, 6, 7) all shipped UI in the existing inline-style-plus-`theme.js` pattern
with zero component library. Phase 8 continues that pattern rather than introducing a parallel system —
initializing shadcn now would fork the design system mid-project against an explicit project constraint,
so the shadcn initialization question was not asked.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/swatch gaps, legend chip padding, KPI tile internal line spacing |
| sm | 8px | Compact element spacing, control internal gaps |
| md | 16px | Default element spacing, tab/control row padding |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions (grandfathered from the existing codebase, reuse verbatim rather than re-deriving):**

- `LayerTabs.jsx` tab button padding is `9px 16px` (not `8px 16px`). The variable picker (D-15: "reads as
  a second tab level") **must reuse this exact `9px 16px` value**, not the theoretical `8px`, so the two
  rows read as one visual system.
- Compact gaps of `5px`/`6px`/`10px` appear throughout `LLMap/index.jsx` and `StatPanel.jsx` (tooltip rows,
  legend swatch gaps, badge padding). These are pre-existing and not to be "corrected" to 4px multiples if
  Phase 8 code sits directly adjacent to them (e.g. legend rows below the new climate map).
- New Phase 8 components (period switcher, variable picker container, two-line KPI tile) should use the
  4px-multiple scale above where there is no adjacent precedent to match. **No exception is granted for any
  new Phase 8 spacing value** — the KPI tile's line-2 → line-3 gap (D-20) uses the `xs` (`4px`) token, not a
  bespoke value; see Typography below.

## Typography

Observed/declared scale (matches the existing app's compact-UI type system — do not introduce a fifth size):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Meta / legend label | 11px | 400 | 1.35 |
| Body / tab label | 13px | 500 (inactive, legacy) / 700 (active) | 1.3 |
| Label (KPI tile heading, uppercase) | 11px | 700 | 1.3 |
| Stat value (KPI tile primary line) | 15px | 700 | 1.2 |
| Stat delta (KPI tile secondary line — **new**, D-20) | 12px | 400 | 1.3 |

**Weight exceptions (grandfathered, not extended to new Phase 8 UI — mirrors the Spacing Scale exceptions
pattern above):**

- `LayerTabs.jsx`'s `500` inactive-tab weight is a **legacy-only** value. It is reused as-is wherever
  `LayerTabs.jsx` itself renders (unchanged, out of this phase's scope), but no new Phase 8 component may
  introduce a third weight — the variable picker's inactive state uses `400`, not `500` (see Variable
  picker spec below), even though it sits directly beside `LayerTabs`.

**Weight contract:** two weights carry all new Phase 8 UI — **400 (regular)** for body/meta/delta text and
**700 (bold)** for values, active states, and labels. New Phase 8 buttons (variable picker, period switcher)
use 400/700 only, matching `StatPanel.jsx` tile typography exactly.

**New tile shape (D-20):** each KPI tile gets a second text line beneath the existing 15px/700 value line —
`{delta value} by 2071–2100` at 12px/400/`C.muted`, e.g. `+2.8 °C by 2071–2100` under `9.4 °C`. This is the
one new typographic role this phase introduces; it must sit inside the same `StatPanel.jsx` tile container
(no new padding/border), directly below the existing value line with a **4px** gap (the `xs` spacing token
— see Spacing Scale; no exception applies, this is a new Phase 8 value with no adjacent legacy precedent).

### Ramp contract (D-11, D-12, D-13) — the core new color surface this phase adds

Two ramp *families* exist, sourced entirely from already-declared `theme.js` tokens (zero new hex values,
matching the Phase 6 D-10/D-11 and Phase 7 D-03 "minimize new colours" rule):

**Heat family** (GDD, bio1) — sequential, warm, light→dark = low→high:
`#fce3da` (`orangeGhost`) → `#eb5b25` (`orange`) → `#dc4b14` (`orangeDark`) → `#bb3f11` (`orangeDeep`)

**Water family** (bio12, bio18) — sequential, cool, light→dark = low→high:
`#00b3ad` (`tealLight`) → `#008581` (`tealMid`) → `#005754` (`teal`) → `#00413f` (`tealBg`)

**Baseline maps (all four variables):** always the sequential ramp for that variable's family, exactly as
above. This is the only ramp baseline maps ever need — D-01's baseline is a snapshot, never a change, so it
is never diverging.

**Change maps:** ramp shape depends on whether the built data's sign varies across the five LLs (D-12,
empirical — confirmed during planning/build, not assumed here):

- **One-signed variable** (expected: GDD, bio1 — both rise everywhere under SSP3-7.0): reuse that
  variable's own sequential family ramp above, unchanged.
- **Sign-varying variable** (expected candidates: bio12, bio18 — precipitation can rise in some LLs and
  fall in others): a 5-class **diverging** ramp built from the same two families as its poles (no new
  hues), centred on the page background as the "near zero" neutral:
  `#dc4b14` (orangeDark, strong decrease) → `#eb5b25` (orange, mild decrease) → `#f9fef9` (`C.bg`, near-zero) → `#008581` (tealMid, mild increase) → `#005754` (teal, strong increase)

If research/build shows a variable's sign does **not** vary as expected, use the sequential form for that
variable instead — do not force a diverging ramp onto a one-signed dataset.

**Legend band count:** 4 classes for every sequential ramp (matches the 4-stop family arrays above exactly
— zero interpolation, zero new intermediate hex values); 5 classes for any diverging ramp (2 decrease + 1
neutral + 2 increase, as listed above).

**Unit-aware legend labels (D-11):** the legend builder must format each band's label per variable family —
temperature-family variables (GDD in °C·d, bio1 in °C) as an absolute delta (`+2.3 °C`, `+310 °C·d`);
precipitation-family variables (bio12, bio18) as **percent change** (`−7 %`), never mm, on change maps.
Baseline-map legend labels use the raw unit (`9.4 °C`, `612 mm`) with no sign.

## Phase-Specific Component Contracts

These extend the template's generic sections with the concrete control specs the planner/executor need,
since this phase introduces two genuinely new UI controls plus one new tile shape.

### Variable picker (D-15, D-19)

- Row of exactly 4 buttons, directly under `LayerTabs`, same horizontal rhythm and `9px 16px` padding as
  `LayerTabs.jsx` buttons (see Spacing exceptions above) — reads as a second tab level, not a dropdown.
- Order: **GDD, bio1 (mean annual temp), bio12 (annual precip), bio18 (precip of warmest quarter)** — GDD
  first and pre-selected on tab open (D-08).
- Active state: 700 weight, `C.orange` text/underline (accent-reserved use #1) — mirror `LayerTabs`'s
  active-tab treatment (bold + colored 2.5px bottom border) exactly, so the two rows visually nest.
- Inactive state: **400** weight (not `LayerTabs`'s legacy `500` — see Typography weight exceptions above),
  `rgba(2,35,34,0.5)`.
- Labels are short variable names, not full scientific descriptions (`GDD`, `Mean temp.` / `Mitteltemp.`,
  `Precipitation` / `Niederschlag`, `Summer precip.` / `Sommerniederschlag`) — full definitions live only in
  the D-14 legend note, never duplicated in the button label.

### Period switcher (D-16, D-17)

- Two-level segmented control, visually attached to the map (on or immediately beside it, per D-15), not
  merged into the variable picker row.
- Level 1: `[Baseline | Change]` — exactly two segments, always visible.
- Level 2: horizon sub-toggle `[2041–2070 | 2071–2100]` — **only rendered when `Change` is the active
  Level-1 segment**; absent (not disabled/greyed) in `Baseline` mode.
- Visual style: segmented-pill pattern, reusing `ProtectedAreasToggle`'s existing pill/border/shadow recipe
  (`border-radius: 10px`, `1px solid C.mutedLight`, `rgba(255,255,255,0.94)` background, `box-shadow: 0 4px
  12px rgba(2,35,34,0.12)`) rather than inventing new chrome.
- Active segment: `C.orange` background or bold `C.orange` text (accent-reserved use #2) — pick whichever
  reads clearest against the pill background at implementation; either satisfies this contract.
- **Phase 10 shared-state note (D-17):** in the two-column comparison view, this control renders once,
  above/beside the single shared `LayerTabs` row, and drives both columns' maps identically — do not
  instantiate a second period switcher per column.

### KPI tile — new two-line shape (D-19, D-20, D-21, D-22)

- Exactly 4 tiles in the Climate tab's `StatPanel` grid (D-19 mirrors the 4 map variables 1:1; the tab's
  KPI count changes from the locked `{climate: 2}` to `{climate: 4}` — planner must update the test
  contract in the same commit as `data/destatis_curated_kpis.json`, per D-18).
- Tile container: unchanged from existing `StatPanel.jsx` tile (`C.white` background, `8px` radius, `1px
  solid C.mutedLight` border, `12px 16px` padding).
- Line 1 (unchanged): 11px/700/uppercase/`C.greenMid` label, e.g. `GDD`.
- Line 2 (unchanged): 15px/700/`C.teal` baseline value, e.g. `1,842 °C·d`.
- Line 2 → Line 3 gap: **4px** (the `xs` spacing token — see Spacing Scale; no bespoke value).
- Line 3 (**new**, D-20): 12px/400/`C.muted`, far-horizon-only delta (D-21), explicitly labelled with the
  year range so it never reads as ambiguous with the baseline line — e.g. `+310 °C·d by 2071–2100` /
  `+310 °C·d bis 2071–2100`. Percent-family variables use the same unit convention as the map legend
  (percent, not absolute mm) — e.g. `−7 % by 2071–2100`.
- Empty/pending value: reuse the existing em-dash (`–`) convention on **both** lines independently — a tile
  may show a baseline value with a pending delta, or vice versa, without inventing a new placeholder glyph.
- Underlying computation (D-22, pipeline concern, not a visual one, listed here only for traceability): area-weighted mean per LL boundary, matching `compute_protected_area_coverage.py`'s projected-CRS clip pattern.

### Lazy-loading affordance (structural, not optional — see CONTEXT "Known hazards")

- Exactly one `(variable × period × slug)` raster may be in flight at a time — reuse the existing
  `SoilStatusBadge`-style loading/error badge (top-left overlay, `C.bg`/`C.teal` info tone or `#dc4b4b`
  error tone) for climate raster fetches, keyed to the new `map.climateLoading`/`map.climateError` i18n
  entries declared in the Copywriting Contract above. No new badge component.
