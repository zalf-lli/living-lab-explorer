<objective>
Build the two-pass machinery D-09 forces and that neither Phase 6 nor Phase 7 needed: a Pass-0 step
that computes one shared colour scale across all five Living Labs and persists it, then a Pass-1
per-Living-Lab tiler that reads those fixed breakpoints and bakes them into pixels.

`08-RESEARCH.md` Pitfall 3 names the exact failure this prevents. `build_colormap()` at
`build_pmtiles.py:30-34` takes a value-to-RGBA dict that must already be known before the per-LL
loop starts, because every prior raster layer was categorical with an a-priori class set. Climate's
mapping is a computed artifact. Running `build_land_cover.py`'s loop verbatim would give five
Living Labs five different-looking scales for the same variable and quietly destroy the point of
D-09 and of Phase 10's comparison view.

No PMTiles are produced by this plan - it writes the machinery and the breakpoints. The 60-file run
is `08-08`.

Purpose: `08-PATTERNS.md` lists `compute_climate_color_breaks.py` as one of only two files in the
phase with no analog anywhere in the codebase. Give it real design attention rather than
force-fitting an existing script's control flow.
Output: two new scripts, one new function in `build_pmtiles.py`, and `data/climate_color_breaks.json`.
</objective>

  <action>
Create `data-pipeline/python/compute_climate_color_breaks.py` with an `argparse` entry point taking
`--layer` (default `chelsa-climate`), `--variable` (repeatable, default all) and `--dry-run`.

Write a module docstring stating the ordering constraint in plain terms: this script must run to
completion before `build_climate_pmtiles.py` starts, because the breakpoints it writes are baked
into PMTiles pixels and must be identical across all five Living Labs (D-09). Say explicitly that
this is the one place in the pipeline where a statistic is pooled across Living Labs before any
per-Living-Lab build, and that computing breaks per Living Lab would silently defeat both D-09 and
Phase 10's two-column comparison.

Modes are `baseline` and `change`, not the three period tokens. The baseline mode pools only the
`baseline` raster. The change mode pools both horizon rasters together, so `2041_2070` and
`2071_2100` share one scale and the trajectory over time reads as a deepening colour rather than as
two independently-stretched maps. Record that reasoning in a comment.

For each variable and each mode:

1. Pool the pixels. For each of the five Living Lab slugs, open the relevant Germany-extent raster
   from `input.path_pattern`, build the clip geometry with `build_clip_geometry(layer, src.crs,
   slug=slug)` - the same function Pass 1 uses, so both passes pool exactly the same pixels - mask
   with `rasterio.mask.mask` using `crop=True`, `all_touched=True` and the declared nodata, drop
   nodata and non-finite values, and concatenate into one pooled array. Assert the per-slug
   contribution is non-empty for every slug before continuing, per CLAUDE.md's assert-non-empty
   rule applied to rasters; a slug contributing zero pixels means the clip missed the raster and
   must fail loudly rather than silently shrink the pool.

2. Decide the ramp shape empirically (D-12). Compute each Living Lab's own mean value for the mode.
   For the `change` mode, if those five per-Living-Lab means span both signs - at least one negative
   and at least one positive - the ramp is `diverging`; otherwise it is `sequential`. The `baseline`
   mode is always `sequential`, because a baseline is a snapshot and never a change, as
   08-UI-SPEC.md states. Store the five per-LL means in the output alongside the verdict so the
   decision is auditable rather than asserted, and print a `[ramp]` line naming the variable, the
   mode, the five means and the verdict. Do not hardcode the expectation that precipitation diverges
   and temperature does not - D-12 states that expectation as something to test, not to assume.

3. Compute the breakpoints. A `sequential` ramp emits 5 boundary values producing 4 bands; a
   `diverging` ramp emits 6 boundary values producing 5 bands. Sequential boundaries are the 0th,
   25th, 50th, 75th and 100th percentiles of the pooled array. Diverging boundaries are symmetric
   about zero: take m as the larger of the absolute 2nd and 98th percentiles of the pooled array and
   emit the six values minus m, minus m over 2, minus m over 6, plus m over 6, plus m over 2, plus m,
   so the middle band is the near-zero neutral. In both cases round every interior boundary to a
   legible step for the variable's unit - 0.1 for degC, 1 for degC-day, 1 for mm, 0.5 for percent -
   and after rounding assert the boundaries are still strictly increasing, widening a collapsed pair
   rather than emitting a non-monotonic ramp.

4. Assign colours. Heat-family variables take the four warm stops; water-family variables take the
   four cool stops; a `diverging` verdict takes the five diverging stops regardless of family, since
   the diverging ramp is built from both families as its poles. Colour lists live as module-level
   constants named `HEAT_RAMP`, `WATER_RAMP` and `DIVERGING_RAMP` carrying the exact hex strings
   locked in 08-UI-SPEC.md, each with a comment naming the `app/src/theme.js` token it corresponds
   to. These are the same values `app/src/data/layers.js` exports; the SUMMARY must note that the
   duplication across the Python and JS sides is deliberate and that `08-08`'s legend codegen is the
   reconciliation point.

5. Write `data/climate_color_breaks.json` (path from `output.color_breaks`) using
   `json.dumps` with `indent=2`, `sort_keys=True` and `ensure_ascii=False`, per CLAUDE.md. Shape: a
   `_meta` block carrying `computed_at`, `source` set to `chelsa`, `input_pattern`, `clip_to` and
   the pooled slug list, mirroring `data/protected_area_kpis.json`'s `_meta`; then one entry per
   variable, each with a `baseline` and a `change` block, and each block carrying `ramp`
   (`sequential` or `diverging`), `breaks`, `colors`, `unit` (from the layer config) and
   `per_ll_means`. Assert that the length of `colors` equals the length of `breaks` minus one before
   writing.

`--dry-run` prints every computed block and writes nothing.
