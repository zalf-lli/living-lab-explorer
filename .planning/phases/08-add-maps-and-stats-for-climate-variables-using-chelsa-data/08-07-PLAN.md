<objective>
Turn the twelve Germany-extent rasters into four per-Living-Lab numbers each — a baseline value and
a far-horizon change — written to their own JSON file.

This is the Phase 05.1 pattern applied to rasters. `compute_protected_area_coverage.py` is a
near-exact structural fit: same `ROOT`/`DATA` constants, same `METRIC_CRS = "EPSG:25832"`, same
`_meta` block, same sorted-key write, same "not registered in sources.yaml, follows the
hardcoded-path pattern" framing. The only substitution is vector dissolve-and-intersect for raster
reproject-mask-and-mean.

The reprojection is not cosmetic. `08-RESEARCH.md` Pitfall 4 spells it out: CHELSA's native grid is
0.0083333 *degrees* per pixel, a fixed angular size, so a plain mean over masked pixels in the
native CRS silently under-weights by latitude. Reprojecting to EPSG:25832 before masking is what
makes an arithmetic mean a genuine area-weighted mean, which is exactly what D-22 asks for.

Purpose: produce the numeric half of the Climate tab. `08-09` merges it into `kpiByTab`.
Output: `data-pipeline/python/compute_climate_kpis.py` and `data/climate_kpis.json`.
</objective>

Add an `argparse` entry point with `--ll` (single-slug print-only dry run, exactly as the analog
does) and `--variable` (repeatable, default all four).

Implement `area_weighted_mean(raster_path, ll_geom_metric)`:
  1. Open the raster with rasterio.
  2. Reproject the whole band to `METRIC_CRS` **before** masking, using
     `calculate_default_transform` for the destination grid and `Resampling.bilinear` for a
     continuous field. This ordering is the entire point: after reprojection every pixel covers the
     same true ground area, so a plain arithmetic mean over the masked pixels *is* the
     area-weighted mean D-22 specifies. Put that sentence in the function docstring, and cite
     Pitfall 4, so a later reader does not "optimise" the reprojection away.
  3. Write the reprojected band into an in-memory dataset (`rasterio.io.MemoryFile`) carrying the
     destination transform, CRS and nodata, then `rasterio.mask.mask` it with the Living Lab
     geometry using `crop=True` and `all_touched=True`.
  4. Convert nodata and non-finite pixels to NaN, assert at least one finite pixel remains — a
     Living Lab yielding zero pixels means the geometry missed the raster and must raise with the
     slug and raster path named, per CLAUDE.md's assert-non-empty rule — then return
     `float(numpy.nanmean(...))`.

Implement `compute_for_slug(slug, boundaries_metric, layer, variables)`:
  - Resolve the Living Lab geometry from `boundaries_metric` by `ll_slug`, raising if absent, the
    same way the analog does.
  - For each variable: compute the baseline mean from `chelsa-{variable}-baseline.tif` and the
    far-horizon change mean from `chelsa-{variable}-2071_2100.tif`. Only the far horizon is read
    for the KPI — D-21 reports 2071-2100 only, and the near horizon stays explorable on the map.
    Read the near-horizon raster not at all, so no reader mistakes an unused value for a bug.
  - Round both figures to a sensible precision for the unit: 1 decimal for degC and percent,
    0 decimals for degC-day and mm. Take the precision from a module-level
    `ROUNDING_BY_UNIT` mapping keyed by the unit strings the layer config declares, so a unit change
    in `sources.yaml` cannot silently change rounding behaviour without a `KeyError`.
  - Emit, per variable, two keys named from the variable's `variable_key`: the key itself carrying
    the baseline value, and `{variable_key}_delta` carrying the far-horizon change. Also emit, once
    per slug, nothing else — the units and horizon live in `_meta`, not repeated per slug.

Implement `main()` mirroring the analog: validate `BOUNDARIES_FILE` exists, has a CRS and an
`ll_slug` column; `gpd.read_file` then `make_valid()` on the geometry column per CLAUDE.md;
reproject once to `METRIC_CRS`; derive `available_slugs` sorted from the boundaries; honour `--ll`
as a print-only dry run that writes nothing.

Write `data/climate_kpis.json` with a `_meta` block carrying `computed_at` (UTC ISO with a trailing
Z, as the analog produces), `source` set to `chelsa`, `metric_crs`, `input_pattern` (the climate
raster pattern), `delta_horizon` set to `2071_2100`, `delta_horizon_label` set to `2071-2100` (the
display form the KPI tile's third line renders), and a `variables` sub-block mapping each
`variable_key` to its `unit` and `delta_unit` `{en, de}` pairs transcribed from the layer config —
this is what lets a percent-change delta sit beneath an absolute baseline (D-11) without the
frontend hardcoding which variables are which family. Then one object per slug. Write with
`json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True)`.

Never read, write or touch `data/destatis_ll.json` — D-23 is explicit that `aggregate_ll()`
destructively regenerates it. Never write `data/ll_content.json`. Add both prohibitions as a
comment near the write.
