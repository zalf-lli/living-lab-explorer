Land the three additive, backward-compatible app-side contracts every later frontend plan depends on,
before any of them exist as consumers: the `VariablePicker` accessibility parameter, the mode-aware source
lookup helper, and the full bilingual string set.

Purpose: `14-RESEARCH.md` Pitfall 3 found that D-03's "VariablePicker needs no modification at all" is

BUEK250. Both fixes are pure additions that change nothing for any existing caller, so they can land in
wave 1 with zero risk while the licence question is still open.

Output: one new hand-written module, one new component prop, and eight new i18n keys per language.
</objective>

     keeps falling through to its current behaviour.

declares (`type`, `yield`), and treat anything else as no mode at all. This is the V5 input-validation
control named in `14-RESEARCH.md`'s Security Domain table — `mode` reaches URL-pattern interpolation in
`resolveLayerAsset`, so it must never be an arbitrary string. Export the closed set as a named constant
(`SOIL_MODE_IDS`) so `layers.js` and the LLDetail state hook can assert against the same list.
