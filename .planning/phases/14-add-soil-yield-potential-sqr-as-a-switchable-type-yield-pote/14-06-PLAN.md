<objective>
Teach the app's single layer-configuration module that one tab can carry two assets of different kinds,
without changing what any existing caller sees.

Purpose: `14-CONTEXT.md` leaves the mechanism to Claude's discretion ("a `modes` map, a second hidden entry,
or an extended `resolveLayerAsset` signature") and `14-RESEARCH.md` Pattern 1 item 5 recommends the `modes`
map plus an extended signature. D-01 makes the constraint sharp: the existing soil entry must stay exactly
what it is today, so a visitor who never touches the new control — and every call site that never passes a
mode — sees the unchanged BUEK map. The yield mode is an addition hanging off it, never a replacement.

Output: one modified file exporting `SOIL_MODES`, a `modes` map on the soil entry, and a `resolveLayerAsset`
that takes an optional `mode`.
</objective>
