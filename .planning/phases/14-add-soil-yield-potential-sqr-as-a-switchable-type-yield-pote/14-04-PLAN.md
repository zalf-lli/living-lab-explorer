<objective>
Bake the national SQR raster into five per-Living-Lab PMTiles pyramids on one shared colour scale, and
publish them.

Purpose: this is the map half of the phase goal. `14-RESEARCH.md`'s "Don't Hand-Roll" table is emphatic that
`build_climate_pmtiles.py`'s clip to reproject to classify to two-stage-mask to MBTiles to PMTiles
orchestration already solves this exact problem, including the buffered-crop-but-true-boundary-alpha-mask
behaviour that the Phase 8 `climate-basemap-hidden-outside-boundary` bug cost a full debug cycle to
discover. Two deliberate deviations apply: nearest-neighbour resampling instead of bilinear (D-13) and
opaque grey nodata instead of transparent (D-10) — the latter requires one small, additive,
backward-compatible parameter on the shared `build_continuous_colormap()`. `14-RESEARCH.md` Pattern 2
confirms no Pass-0 colour-breaks script is needed: D-11's bands are arithmetic, declared in `sources.yaml`,
not derived from the pixel distribution.

Output: an extended shared colormap helper with its own unit test, a new build script, and ten committed
`.pmtiles` files (five in `data/pmtiles/`, five published to `app/public/data/pmtiles/`).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party GeoTIFF -> rasterio -> committed tiles | A 2.2 MB BGR raster already in the repo is decoded and re-encoded by the build |
| `sources.yaml` patterns -> filesystem writes | `pmtiles_pattern` and the temp-dir root are interpolated into write paths |
| external CLI (`pmtiles`, `rio`) invocation | `subprocess.run` with a binary located via PATH or the `PMTILES_BIN` env var |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-11 | Tampering | Untrusted raster input decoded by rasterio/GDAL | accept | The file is committed in-repo, shipped by BGR, 2.2 MB, and decoded only at build time by a developer — never at request time by a visitor. No runtime decode surface is created |
| T-14-12 | Denial of service | Unbounded build output committed to git | mitigate | Task 3 asserts a hard 20 MiB two-copy footprint ceiling and halts rather than committing past it, mirroring the Phase 8 `08-08` budget-gate discipline |
| T-14-13 | Tampering | `subprocess.run` of the `pmtiles` CLI | mitigate | Reuses the existing `find_pmtiles_bin()` / `convert_pmtiles()` path with a list-form argv (no shell), unchanged from every prior raster phase |
| T-14-14 | Information disclosure | Publishing data outside the true Living Lab boundary | mitigate | The `buffer_m=0` geometry mask forces alpha 0 for every pixel outside the unbuffered boundary, applied after classification so the D-10 grey cannot leak into the 2 km ring |
| T-14-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages — rasterio, numpy, geopandas and the pmtiles/rio CLIs are all already pinned and exercised by Phases 6/8; `data-pipeline/requirements.txt` must be unchanged |
</threat_model>
